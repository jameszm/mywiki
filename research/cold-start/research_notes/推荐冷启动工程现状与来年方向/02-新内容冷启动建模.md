## KQ1 内容侧表征用于冷启动：多模态 embedding 直接作为冷启 item 表征、对齐到协同空间的方法、冷/热阶段的表征切换

### Takeaway
2025 年中以来公开上线的方案没有一家把"冻结多模态向量直接喂排序"作为冷启动主方案；共同模式是 **"冻结 MLLM/CLIP 编码 → 用行为监督对齐到协同/ID 空间（对比学习对齐 warm item 的 ID embedding、co-click 对比、残差对齐码本）→ 作为 ID 的代理/补充进入现有排序或双塔"**，并且用**显式的成熟度门控或掩码**在冷/热之间切换（小红书 IDProxy 的残差门控、阿里国际 GateSID 按交互数与上架时长的门控、Netflix 的 collaborative-embedding masking、Pinterest 的非历史特征残差连接、Tubi 的"内容塔不带 ID"）。公开收益集中在新内容切片：IDProxy 对 <24h 新 item 的 AUC 增益是全局的 2 倍（+0.23–0.32% vs +0.12–0.15%）、淘宝 SaviorRec 冷启 clicks +13.21%/orders +13.44%、Pinterest "Warmer for Less" 新内容互动 +10%、MESH 新 Pin repin +5.5%、微信 Tlow 新 item CTR +11.64%、快手电商搜索 SMILE 新品 CTR +1.66%。学术侧的两条警告值得工程师记住：内容→协同的映射会**继承并放大热门偏差**（内容像爆款的冷品被高估），以及冷/热表征的**"跷跷板"**（提升冷品常损伤热品）。

### Cited Findings

**(a) 已上线并公开收益：MLLM/多模态代理 ID、行为对齐、残差/门控注入**
- 小红书 **IDProxy**（arXiv 2603.01590，2026-03）：用冻结 MLLM（InternVL）从内容生成 **proxy embedding，显式对齐到现有 ID embedding 空间**，并与 CTR 排序模型端到端联合优化；两阶段：阶段 1 把 MLLM 末层聚合向量经 MLP 投影后用对比损失对齐 ℓ2 归一化的 warm item ID embedding（Proxy Alignment Loss），阶段 2 用 k-means 选出的 MLLM 层子组抽多粒度表征、轻量 adaptor 融合、与粗 proxy **残差门控**合并后作为"类 ID 特征"注入排序主干；**新 item 的 proxy 离线预计算，排序时查表**。离线 AUC +0.14%；**<24h 新 item AUC +0.23–0.32%，是全局 +0.12–0.15% 的约 2 倍**；内容流 Time Spent +0.22%、Reads +0.39%、Engagement +0.5%；展示广告 Advertiser Value +1.93%、COST +1.73%、CTR +0.23%；已部署于小红书 Explore Feed 内容流与展示广告，日服务数亿用户。— [arXiv 2603.01590](https://arxiv.org/abs/2603.01590)（摘要 [A]）；细节与分切片数字转引自 [memgrafter 摘要](https://github.com/memgrafter/research-digests/blob/main/ml_research_analysis_2026/2603.01590_idproxy-cold-start-ctr-prediction-for-ads-and-recommendation-at-xiaohongshu-with-multimodal-llms_20260401_024856.md)（[B]）。**已上线并公开收益。**
- 淘宝 **SaviorRec**（arXiv 2508.01375，2025-08）：先用 co-click 对比学习微调多模态编码器得到 behavior-aware embedding（SaviorEnc），再用 RQ-VAE 量化成层次 SID，SID 索引一个**零初始化的 MBA 码本学习残差对齐向量**，双向 target attention 融合行为特征与对齐后的多模态特征；MBA 与 DNN 联合训练、编码器冻结。AUC +0.83%，冷启 item clicks +13.21%、长尾 item orders +13.44%，i2i 召回 Hit@30 +10.72%。— [arXiv 2508.01375](https://arxiv.org/abs/2508.01375)（摘要 [A]）；机制与数字转引自 [memgrafter](https://github.com/memgrafter/research-digests/blob/main/ml_research_analysis_2025/2508.01375_saviorrec-semantic-behavior-alignment-for-cold-start-recommendation_20260211_032636.md)（[B]）。**已上线并公开收益。**
- 阿里国际 **GateSID**（arXiv 2603.22916，2026-03）：RQ-VAE 把多模态特征离散成层次 SID，**自适应门控按 item 成熟度（交互数、上架时长等统计特征）动态平衡语义与协同信号**：Gating-Fused Shared Attention（模态内注意力 + item 级门控权重融合）与 Gate-Regulated Contrastive Alignment（冷品加强语义-行为一致性约束、热品放松以保留协同信号）；线上 **GMV +2.6%、CTR +1.1%、orders +1.6%，额外延迟 <5 ms**（daiwk 转述：20% 流量两周）。— [arXiv 2603.22916](https://arxiv.org/abs/2603.22916)（摘要 [A]）；[daiwk 复现笔记](https://github.com/daiwk/auto-research/blob/main/docs/reproductions/2603.22916-gatesid/README.md)、[memgrafter](https://github.com/memgrafter/research-digests/blob/main/ml_research_analysis_2026/2603.22916_gatesid-adaptive-gating-for-semantic-collaborative-alignment-in-cold-start-recommendation_20260403_060441.md)（[B]）。**已上线并公开收益。**
- 快手电商搜索 **SMILE**（arXiv 2510.12604，2025-10）："现有方法把 item 内容与协同信息对齐来把热门品的协同信号迁移给冷品，但忽略了协同与内容的不对称性以及 item 间的细粒度差异"；用 **RQ-OPQ** 同时量化内容与协同信息，RQ 编码跨 item 迁移共享协同信号、OPQ 编码学习 item 差异化信息；线上 **item CTR +1.66%、买家 +1.57%、订单 +2.17%**。— [arXiv 2510.12604](https://arxiv.org/abs/2510.12604)（摘要 [A]）。**已上线并公开收益。**
- 阿里 **MIM**（arXiv 2502.00321，2025-02，淘宝搜索广告）：三阶段（预训练 → Content-Interest-Aware SFT → 把多模态内容兴趣注入 CTR 模型）；工程上专门设计 **Real-time Inference Module（RIM）：新 item 一上线就实时推断其 MM embedding，以 window message 送入 MM 表（供离线训练）与参数机（供在线服务）**；按 item 年龄分 10 组（S1 最新 → S10 最老）评估，**最新组 AUC 增益最大**；淘宝搜索广告三次发布累计 AUC +0.81pt、线上 CTR 累计 +14.14%。— [arXiv 2502.00321](https://arxiv.org/abs/2502.00321)；本地全文镜像 `guyulongcs/...MIM - Multi-modal Content Interest Modeling Paradigm...pdf`（[A] 全文）。**已上线并公开收益。**
- Pinterest **Warmer for Less**（arXiv 2512.17277，2025-12；WWW'26）：从真实流量诊断出四个冷启根因并逐一解决：(1) 算力约束 → 全部改动只增加 **5% 参数**；(2) 冷品只有非历史（内容/属性）特征而模型默认轻视它们 → **为非历史特征加残差连接**；(3) 冷品预测分系统性偏低 → **冷/非冷分数的 score regularization**；(4) 冷品标签稀疏 → **manifold mixup**；合起来 **Pinterest 新内容互动 +10%**，整体互动与成本不受损，服务 5.7 亿用户。— [arXiv 2512.17277](https://arxiv.org/abs/2512.17277)（摘要 [A]）；搜索摘要另称"冷启正样本分数比非冷启低 8–14%"、"新 Pin 指标 +2.5%～6%"（[C]，未核实）。**已上线并公开收益。**
- Pinterest **MESH**（arXiv 2607.12392，2026-07，Related Pins 十亿级 i2i）："为覆盖 fresh 与长尾内容，现代系统通常退化为一个碎片化的专用召回模型'动物园'"；提出 Scaling Bias of Heterogeneity（模型容量增益在不同内容层级上不均等），用**按特征域划分的模块化架构 + 门控偏差修正**隔离稀疏 item 信号与高频互动特征的梯度；**fresh item 的幂律缩放指数提升 14 倍**；线上 **fresh-item repins +5.5%、漏斗效率 +55%、用户留存 +0.46%**，异步服务吞吐 2.87 倍。— [arXiv 2607.12392](https://arxiv.org/abs/2607.12392)（摘要 [A]）。**已上线并公开收益。**
- Pinterest **PinFM**（arXiv 2507.12704，2025-07）：20B+ 参数用户行为序列基础模型，"必须能处理预训练阶段不存在的新 item"；通过改变输入序列让模型学习序列与候选 item 的交互，**新 item 互动 +20%**。— [arXiv 2507.12704](https://arxiv.org/abs/2507.12704)（摘要 [A]）。**已上线。**
- Tubi **Shallow-RHS**（arXiv 2606.06225，2026-06）：服务接口约束"新内容必须立即获得独立 embedding，且用户侧需要可做 ANN 的向量"；把冷启动建模为时间二部图上的归纳式补全：左塔（设备）用时间合法的观看历史做消息传递，**右塔（内容）故意"图上浅层"——不用 ID embedding、不用内容侧子图、不用邻居聚合、不用任何交互派生表征，强迫内容编码器把内在特征映射进 CF 感知空间**；训练后同一编码器为 warm 与新内容生成 embedding，通过检索 warm 代理邻居实现隐式图补全；线上实验显示内容冷启互动、**晋升速度（promotion speed）**、曝光获取与设备冷启互动一致提升（无百分比）。— [arXiv 2606.06225](https://arxiv.org/abs/2606.06225)（摘要 [A]）。**已上线，无数字。**
- Netflix **Towards Generalizable and Efficient Large-Scale Generative Recommenders**（arXiv 2605.23312，2026-05）：主干从 2M 扩到 1B 参数；明确指出"**新上线的 title 需要在协同 ID embedding 可靠之前就从语义元数据打分**"，方案是**语义 item tower + collaborative-embedding masking** 做冷启适配；一周生产 shadow 评估（100 万用户）1B 模型在所有任务 MRR 高于 2M 基线。— [arXiv 2605.23312](https://arxiv.org/abs/2605.23312)（摘要 [A]）。**有论文（shadow 评估），未确认全量上线。**
- 微信 **Tlow**（arXiv 2608.24176，2026-08）：流模型把语义 embedding 变换到标准正态潜空间后做独立 tokenization；在"中国最大社交媒体平台微信"的多模态召回任务线上实验，**token-ID 召回模型使 CTR 全局 +10.32%、新 item +11.64%**。— [arXiv 2608.24176](https://arxiv.org/abs/2608.24176)（摘要 [A]）。**已上线并公开收益。**

- Netflix 多模态资产个性化（CLIP 入双塔显著改善冷启动，2608.18322）、Pinterest PinCLIP（新 organic Repin +15%、新广告 click +8.7%）、TikTok FLUID（候选侧完全去 ID、冷启直播间观看 +2.05%）、快手 QARM 系、字节 TRM（<1 天新品 AUC +0.06%）详见 06 笔记 KQ1。

**(b) 冷/热表征切换的具体做法（跨来源归纳，均有出处）**
- 按成熟度门控：GateSID（交互数/上架时长 → 门控权重；[A]）；小红书 IDProxy（粗 proxy 与细 proxy 残差门控；[B]）；快手 **DAS/PIT** 与 Meta FlexCode（流行度感知的 MoE 路由在 CF 码本与语义码本间分配 token 预算：头部多 CF token、尾部多语义 token，离线头部 +3.0%、尾部 +11.3%，工业数据集验证但未报上线；[arXiv 2511.20673](https://arxiv.org/abs/2511.20673) 摘要 [A]，数字转引 [memgrafter](https://github.com/memgrafter/research-digests/blob/main/ml_research_analysis_2025/2511.20673_semantics-meet-signals-dual-codebook-representationl-learning-for-generative-recommendation_20260210_235339.md) [B]）。
- 按阶段掩码/课程：Netflix collaborative-embedding masking（[A]）；eBay 系作者的 **Representation Curriculum**（arXiv 2606.09891，2026-06）：训练时先只用内容类"merit"信号，再引入曝光依赖的"belief"信号（流行度、CTR/CVR 聚合、ID 表征）并把内容通路锚定在已学表征附近，避免"捷径依赖"和内容信号的梯度饥饿；在大规模电商搜索的随机化线上实验中冷门群体一致提升、头部有受控的 trade-off。— [arXiv 2606.09891](https://arxiv.org/abs/2606.09891)（摘要 [A]）。**已上线，无数字。**
- 按流行度分任务：快手作者的 **PAM**（KDD 2025，"Online Item Cold-Start Recommendation with Popularity-Aware Meta-Learning"）：按预设流行度阈值把流式数据切成元学习任务，让模型在不同流行度层级上区分并重加权行为特征与内容特征，并为低流行度任务加数据增强与自监督损失；强调 fine-tune/知识迁移类离线方案"在流式数据管线上不可行"。— [ACM DOI 10.1145/3690624.3709336](https://doi.org/10.1145/3690624.3709336)（摘要经 [Doragd KDD 2025 索引](https://github.com/Doragd/Algorithm-Practice-in-Industry/blob/main/paperBotV2/conf_summary/data/papers/kdd/kdd2025.md) [B]）。
- 冻结 + 小增量：**"Let It Go? Not Quite"**（arXiv 2507.19473，2025-07）：直接用冻结内容向量次优，完全微调又让冷品表征漂离原语义结构，提出在冻结内容 embedding 上加小的可训练 delta；**DenseRec**（arXiv 2508.18442，2025-08）：学一个从稠密内容空间到 ID 空间的线性投影、双路径，指出"稠密内容向量直接接入 transformer 序列模型一直不如纯 ID"。— [arXiv 2507.19473](https://arxiv.org/abs/2507.19473)、[arXiv 2508.18442](https://arxiv.org/abs/2508.18442)（摘要 [A]，仅研究）。
- 去 ID：Tubi 内容塔、FLUID 候选侧（短生命周期内容）。

**(c) 学术警告（仅研究，但直接影响工程设计）**
- **继承的热门偏差**（arXiv 2510.11402，2025-10）：冷启模型用 warm CF 模型做监督会复制其热门偏差，且更严重——冷品无法从交互推断流行度，只能从内容估计，导致"内容像爆款"的冷品被显著高估；用 embedding 模长作流行度代理做后处理可缓解。— [arXiv 2510.11402](https://arxiv.org/abs/2510.11402)（摘要 [A]）。
- **跷跷板**（DiffCold，arXiv 2606.12245，2026-06）：现有内容→协同映射"普遍"存在提升冷品即损伤热品的现象，根因是 warm embedding 处在行为流形、cold embedding 处在语义流形，硬映射牺牲 warm 精度；用条件扩散从内容重建 warm embedding，检索相似 warm item 初始化生成。— [arXiv 2606.12245](https://arxiv.org/abs/2606.12245)（摘要 [A]）。
- 纯内容的 item-item 相似建模（SEMCo，arXiv 2604.12990）与**稀疏内容表征**（arXiv 2607.17184，稀疏向量在冷启召回精度与存储成本上优于稠密向量）；多模态 MoE（MAMEX 2508.08042）、M²VAE（AAAI 2026）、MoToRec（AAAI 2026）均为公开数据集研究。— 摘要 [A]（CSQianDong 镜像）。
- 2026 年 2 月 Kuaishou 与学界合作的 **KuaiSearch** 等数据集、VK-LSVD（新视频→100 个用户任务）为冷启研究提供工业规模数据（见 06 笔记）。

### Inferences
- 把 MLLM 表征当"ID 的代理"并**在 ID 空间里对齐**（IDProxy/SaviorRec/Tubi/Netflix）而非在语义空间里重建协同，是 2026 年工业方案的共同选择：它保留了现有排序主干（无需重训），冷品靠 proxy、热品靠 ID，切换靠门控/掩码而非两套模型。
- 公开的冷启切片增益（+10%～+20%）与全局增益（+0.1%～+0.5%）相差两个数量级，说明新内容表征的价值主要体现在"让新内容能被公平打分"而非提升整体精度；评估时必须按 item 年龄/曝光分桶（MIM S1–S10、IDProxy <24h、TRM <1 天都是这样报的）。
- 热门偏差继承 + 跷跷板两个学术发现解释了为什么工业方案普遍加入**分数正则/校准**（Pinterest、PinEqualizer）和**成熟度门控**：没有它们，内容→协同映射会把"像爆款的新内容"推得过高、又把热品拉低。

### Gaps
- 没有任何公开资料给出"多模态 proxy 覆盖一条新视频需要多少秒/多少 GPU"；MIM 的 RIM 只说"short window time"。
- IDProxy/GateSID 的排序主干结构、MLLM 提示与聚合函数、冷切分口径均未披露（memgrafter 限制项）。
- Zalando 2507.19346 的具体线上数字无法读取（arXiv 屏蔽）。

## KQ2 ID embedding 预热与生成：从内容生成 ID、meta-learning 后续、扩散/生成式 ID、warm-up 网络、ID 与内容的混合门控、随曝光增加的平滑过渡

### Takeaway
"从内容生成新 item 的 ID embedding"这条线（Meta-Embedding 2019 → MWUF 2021 → CVAR 2022 → 扩散式 CSDM/DiffCold 2025–2026）在学术上仍活跃，但 **2025–2026 公开上线的工业方案几乎都不再单独生成一个"假 ID 向量"**，而是三种替代形态：(1) **代理特征注入**——冷品用内容 proxy/SID 占据 ID 的位置并与主干联合训练（IDProxy、SaviorRec MBA、GateSID）；(2) **参数生成/超网络**——LLM 直接生成冷启 CTR 估计器的权重（Walmart 系 LLM-HYPER，已上线）；(3) **基础设施层面保证新 ID 有干净的槽位与秒级新鲜度**——Meta MPZCH（新视频曝光 +0.83%）与 Memory Layer（新鲜度 5 分钟 → 20 秒、冷启互动 +5–6%）。平滑过渡靠成熟度门控（GateSID）、流行度分层任务（PAM）、分数正则（Pinterest）与去 ID 时的分阶段 warmup（FLUID），而不是靠"ID 学好后切换"。

**(a) 经典背景（2017–2024，标注年份）**

**(b) 2025–2026：生成式/扩散式 ID 预热（仅研究）**
- **CSDM**（AAAI 2025，arXiv 2504.06270，2025-04）：在 ID embedding 空间与边信息空间之间定义扩散过程，生成"预热后"的 embedding；非马尔可夫性质允许用子序列加速训练；同时用变分推断与 BCE 监督，**对冷启阶段与 warm-up 阶段的 item 都能生成**；三个公开数据集。— [arXiv 2504.06270](https://arxiv.org/abs/2504.06270)（摘要 [A]）；AAAI 页面 [ojs.aaai.org 33469](https://ojs.aaai.org/index.php/AAAI/article/view/33469)（[C]）。**仅研究。**
- **DiffCold**（arXiv 2606.12245）：条件扩散从内容重建 warm embedding + 检索增强聚合器 + 模拟式表征对齐，声称解决跷跷板。**仅研究**（见 KQ1）。
- **BPE token 级 LLM embedding 初始化**（arXiv 2509.13179，2025-09）：用子词级 LLM 向量做零样本初始化。**仅研究。**
- **SwapRec**（arXiv 2609.00913，2026-09）：工业常用的推理期启发式——把序列里的冷 item 换成最相似的 warm 邻居——序列模型对此并不鲁棒，SwapRec 在训练期就做同样的 swap，使冷 item 交互不再污染实时个性化、且推荐列表中冷 item 占比上升。— [arXiv 2609.00913](https://arxiv.org/abs/2609.00913)（摘要 [A]）。**仅研究，但描述了一个真实工业启发式。**
- **GenRecEdit**（arXiv 2603.14259）把 NLP 的模型编辑搬到生成式推荐：训练-free 地把冷启 item 的多 token SID 注入模型（见 KQ5）。

**(c) 2025–2026：工业上线的"预热"形态**
- **代理特征注入**：IDProxy（MLLM proxy 对齐 ID 空间并端到端训练，[A]/[B]）、SaviorRec（SID 索引零初始化残差对齐码本，[B]）、GateSID（成熟度门控，[A]）、Netflix（语义 tower + 协同 embedding 掩码，[A]）、Pinterest Warmer for Less（非历史特征残差连接，[A]）。详见 KQ1。
- **LLM 作为超网络直接生成冷启 CTR 模型参数**：**LLM-HYPER**（arXiv 2604.12096，2026-04，作者单位为美国头部电商平台）：少样本 CoT 提示 + 多模态广告内容（文本+图），用 CLIP 检索语义相似的历史 campaign 作示例，让 LLM **推断线性 CTR 预测器的逐特征权重**；为可服务性加入归一化与校准，使生成权重对齐生产 CTR 分布；离线 NDCG@10 +55.9%；**线上 A/B 显示"大幅缩短冷启动期"并达到有竞争力的表现，已生产部署**。— [arXiv 2604.12096](https://arxiv.org/abs/2604.12096)（摘要 [A]）。**已上线，无百分比。**
- **Meta MPZCH**（arXiv 2602.17050，2026-02，Multi-Probe Zero Collision Hash）：用线性探测 + 辅助张量追踪 ID→槽位映射，支持 TTL/LRU 驱逐；**新 ID 获得专属槽位或驱逐过期 ID，驱逐时同时重置 embedding 权重与优化器状态以防负迁移**；已集成 TorchRec 并生产部署；线上：用户 embedding 零碰撞、17 个排序任务中 14 个 NE 改善；**新视频曝光 +0.83%、同一作者 item 的 embedding 相似度 25% → 38%**；训练 QPS 与推理延迟与基线持平。— [arXiv 2602.17050](https://arxiv.org/abs/2602.17050)；数字转引 [memgrafter](https://github.com/memgrafter/research-digests/blob/main/ml_research_analysis_2026/2602.17050_multi-probe-zero-collision-hash-mpzch-mitigating-embedding-collisions-and-enhancing-model-freshness-in-large-scale-recommenders_20260404_112958.md)（[B]）。**已上线并公开收益。**
- **Meta Memory Layer**（arXiv 2607.25110，2026-07，Instagram Reels 早期排序）：把服务时的 item embedding 缓存改成**与模型共训的 in-model KV 表**（item tower 训练时写入、服务时读取，单一事实源）；**always-on embedding（作者、topic 等属性）覆盖尚未入缓存的 item，使每个 item 都能被打分**；预测覆盖率 96% → 100%，**embedding 新鲜度 O(5 min) → O(20 s)**，训练-服务 NE gap 缩小最多 86%（pselect 12.11% → 1.64%）；**最新内容召回 >2 倍、冷启互动 +5–6%**；训练+发布算力 -30%、服务算力中性；daiwk 转述回测：1 小时内媒体播放 +6～7%，5 分钟内媒体 >2×。— [arXiv 2607.25110](https://arxiv.org/abs/2607.25110)（摘要 [A]）；[daiwk 复现笔记](https://github.com/daiwk/auto-research/blob/main/docs/reproductions/2607.25110-memory-layer/README.md)（[B]）。**已上线并公开收益。**
- 抖音 **AdaF²M²**（arXiv 2501.15816，2025-01）：长尾分布导致模型过度依赖 ID 类特征、非 ID 元特征学不充分；用**特征掩码多前向训练**让模型全面学习特征，**adapter 按用户/item 所处状态自适应加权特征**；在抖音集团多应用的召回与排序广泛部署，用户活跃天数累计 +1.37%、使用时长 +1.89%。— [arXiv 2501.15816](https://arxiv.org/abs/2501.15816)（摘要 [A]，CSQianDong 镜像）；搜索摘要称其在抖音音乐 App 的 item 冷启动任务（双塔冷启模型）上两周以上 A/B 提升冷启 item 的曝光、item 数、Like 与 Finish（[C]，未核实）。**已上线并公开收益（冷启切片数字未核实）。**

**(d) 平滑过渡的公开做法**
- 成熟度门控（GateSID）、流行度分层任务（PAM）、冷/非冷分数正则（Pinterest Warmer for Less；PinEqualizer 的 fresh/old 正则与分内容类型校准）、去 ID 的三阶段 warmup（FLUID：加 slice 码 → 去 ID → 加 room 码；06 笔记）、Representation Curriculum 的"先内容后曝光信号"课程、Soft Curriculum 的损失退火（KQ4）。

### Inferences
- 学术上"生成 ID embedding"的问题设定（给冷品一个近似 warm 的向量）在工业里被**基础设施**改写：只要新 ID 能在秒级拿到干净槽位（MPZCH）并在 20 秒内被训练写回（Memory Layer），"预热"更多靠**真实早期反馈 + 内容代理**而非生成模型；这解释了为什么 2025–2026 没有看到扩散式 ID 预热的上线案例。
- LLM-HYPER 的"生成模型参数而非 embedding"是另一个工程上可行的方向：它绕开了 ID 空间对齐问题，把冷启期的打分器变成线性可校准模型，与主模型解耦。
- "ID 与内容混合门控"已经从研究走到上线（GateSID <5 ms），门控输入统一是**交互计数 + 上架时长**这类可在线获取的统计量。

### Gaps
- 没有 2025–2026 的公开案例给出"ID embedding 从冷到热需要多少曝光/多少小时"的量化曲线；POSO 的新视频阈值 T_dv 与曝光阈值数值未披露。
- Meta-Embedding/MWUF/CVAR 一类方法在 2025–2026 是否仍在任何平台生产使用，无公开资料。
- LLM-HYPER 的线上百分比、AdaF²M² 冷启切片数字未能核实。

## KQ3 语义 ID 在冷启动上的真实作用：共享码本的泛化收益、碰撞对冷启动的影响、动态码本与新内容分配、"SID + ID 双用"

### Takeaway
SID 对冷启动的收益是**真实但有边界的**：(1) 公开的上线数字一致显示新内容切片受益最大（Google 2023 新品 CTR +2.8–3.5%、Meta prefix-ngram 新品 NE -0.41%、快手 OneSearch 新品 CTR +3.31%、QuaSID 冷启召回订单 +6.42%、抖音 GEAR 冷启广告激活 +1.46%、头条 R3-VAE 冷启 +15.36%、京东 SA²CRQ 尾部覆盖 +79.6%、微信 Tlow 新 item CTR +11.64%）；(2) 但 2026 年三篇诊断性研究证明 **SID 生成"可组合但不开放"**：新 item 若落在未见过的原子 token 或弱支持的 SID 路径上，生成式模型几乎不可达（ColdSID、GenRecEdit 的"冷启坍缩到近零"、DREAM 的"早期静态分配是根本瓶颈"），且 SID 级命中会把 item 级指标高估最多 103%；(3) 碰撞治理的冷启收益有限（OneMall 36%→11% 仅 +4.4% HR），真正的工程重心转向**动态码本与新 item 的秒级分配**（快手 GR4AD 新广告"按内容算 UA-SID、秒级更新双向索引"；快手单层大码本的曝光感知动态更新 +0.792%；字节 MERGE；快手 PIT +0.402%；TAGR 直播广告 LSID 周期刷新 +16.1% 收入）；(4) "SID + ID 双用"是排序侧主流（Meta prefix-ngram + 哈希 ID、字节 TRM mem-token、短视频搜索 SID-Coord 的 HID-SID 目标感知门控 +0.664% 长播率、Google 双用途 SID、快手单层码本的"协同消歧 token"）。

### Cited Findings

**(a) SID 让新内容共享码本的泛化收益（已上线并公开收益）**
- Google/YouTube 2023（arXiv 2306.08121）：长尾与全新物品 CTR +2.8～3.5%、embedding 参数 -15%（06 笔记，[B]）；Meta 2025（arXiv 2504.02137）：SID prefix-ngram 新品 NE -0.41%、线上广告排序 NE +0.15%（06 笔记，[B]）。
- 快手 **QuaSID**（arXiv 2603.00632，2026-02/03）：Hamming 引导的 margin 排斥 + 冲突感知的有效对掩码 + 双塔对比注入协同信号；**快手电商 5% 流量：排序 GMV-S2 +2.38%，冷启召回完成订单最高 +6.42%**。— [arXiv 2603.00632](https://arxiv.org/abs/2603.00632)（摘要 [A]）；[daiwk](https://github.com/daiwk/auto-research/blob/main/docs/reproductions/2603.00632-quasid/README.md)（[B]，"5% 流量五天"）。
- 快手 **AdaSID**（arXiv 2604.23522）：电商短视频召回 GMV +0.98%（06 笔记，[A]）。快手 **OneSearch** 7 天内新品 CTR +3.31%（[B]）。抖音 **GEAR** 冷启广告激活率 +1.46%（[B]）。头条 **R3-VAE** 冷启 +15.36%（[B]）。详见 06 笔记 KQ3。
- 京东 **SA²CRQ**（arXiv 2602.23978，2026-03）：头部 item 受碰撞之害、尾部/冷启 item 泛化不足的 trade-off；SARQ 按路径熵动态分配码长（头部更长更可辨、尾部更短更可泛化），ACRQ 用头部冻结的语义流形作锚点正则并加速尾部表征学习；工业搜索系统：Recall@2k 相对 TIGER +12.1%、幻觉率 0.2514 → 0.1808、**尾部 item 检索覆盖 +79.6%（509 → 914 个/query）**；**线上 A/B 转化率 +0.13%、用户价值 +0.42%；30 QPS、TP99 50 ms**。— [arXiv 2602.23978](https://arxiv.org/abs/2602.23978)（摘要 [A]）；数字转引 [memgrafter](https://github.com/memgrafter/research-digests/blob/main/ml_research_analysis_2026/2602.23978_towards-efficient-and-generalizable-retrieval-adaptive-semantic-quantization-and-residual-knowledge-transfer_20260403_170557.md)（[B]）。**已上线并公开收益。**
- 微信 Tlow 新 item CTR +11.64%（[A]，KQ1）；快手电商搜索 SMILE（RQ 迁移协同、OPQ 学差异；[A]，KQ1）；淘宝 **FORGE**（arXiv 2509.20904）给出两个与效果正相关的免训练 SID 质量指标并使线上收敛时间减半（06 笔记，[A]）。

**(b) 碰撞对冷启动的影响与"SID 评测高估"**
- **How Reliable Are Semantic-ID Tokenizer Comparisons**（arXiv 2605.25330，2026-05）：四个数据集五种 tokenizer 上，**卷入碰撞的 item 比例最高 30.5%**；SID 级匹配只能识别碰撞组而非目标 item，**Hit@10 被高估最多 103.36%**，且高估随碰撞率上升；提出碰撞感知的 item 级指标与"最小代价重分配末级 SID"的后处理。— [arXiv 2605.25330](https://arxiv.org/abs/2605.25330)（摘要 [A]）。**仅研究。**
- 快手 OneMall：Res-Kmeans + FSQ 把碰撞 36% → 11%，但 HR@50 仅 33.9% → 35.4%（"不成比例"）；QARM V2 碰撞 77.92% → 32.39%（06 笔记，[B]）。
- 阿里 **ColdSID "Can Generative Recommendation Reach Cold Items? A Temporal Perspective"**（arXiv 2607.21101，2026-07）：在绝对时间协议下分离 seen/unseen 目标并在 token 级诊断冷 item 可达性；**SID 模型偶尔能到达"由已观测 token 与前缀支持"的未来 item，但对未见原子 token 与无支持的 SID 路径几乎无能为力**；把 SID 生成解释为层次语义分桶（前几 token 选粗语义区、后 token 细化 item 路径），结论"compositional but not fully open-ended"，建议更独立的 SID 空间、打分式接口与动态文本上下文。— [arXiv 2607.21101](https://arxiv.org/abs/2607.21101)（摘要 [A]）。**仅研究（阿里作者）。**
- **GenRecEdit**（arXiv 2603.14259，2026-03）："现有 GR 模型存在严重的冷启坍缩：冷启 item 的准确率可降到接近零"；模型编辑按 SID 位置逐 token 注入（用元数据检索相似 warm item 的前序交互作伪历史），一对一触发防干扰；**Phone 数据集冷启 NDCG@10 从 ~0 升到 0.0052，warm 仅降 6.5%（微调式编辑降 87%），只需重训 9.5% 的算力**。— [arXiv 2603.14259](https://arxiv.org/abs/2603.14259)（摘要 [A]）；数字 [memgrafter](https://github.com/memgrafter/research-digests/blob/main/ml_research_analysis_2026/2603.14259_bringing-model-editing-to-generative-recommendation-in-cold-start-scenarios_20260404_233108.md)（[B]）。**仅研究。**
- **DREAM**（arXiv 2606.06947，2026-06，作者含快手研究人员）："当前 SID 方法在观察到足够反馈之前就通过离线 tokenization 给每个 item 一个静态标识；对冷启 item 这种一次性承诺产生判别性差的码，错位路径因相关 token 训练中很少被采样而得不到修正。**我们认为这种早期静态承诺、而非模型容量，是 SID 生成式推荐冷启的根本瓶颈**"；三阶段：意图感知 tokenizer 用反事实对比学习为每个冷 item 生成多个行为对齐候选 SID → 冻结主干作评估器按多上下文用户支持选最可靠候选（无需重训）→ 训练与推理中维持多条加权 SID 假设的动态 beam；三个 Amazon 数据集冷启指标大幅领先。— [arXiv 2606.06947](https://arxiv.org/abs/2606.06947)（摘要 [A]）。**仅研究。**
- **SID 过期（staleness）**（arXiv 2604.13273，2026-04）：协同感知 SID 随交互漂移而过期；提出轻量、模型无关的 SID 对齐更新，把用近期日志刷新的 SID 对齐到现有词表，使 retriever checkpoint 兼容、可 warm-start 微调，**比全量重建-重训省 8–9 倍 retriever 训练算力**。— [arXiv 2604.13273](https://arxiv.org/abs/2604.13273)（摘要 [A]）。**仅研究。** 另见 Drift-Aware Continual Tokenization（2603.29705）与 2603.29845 复现研究（KQ5）。

**(c) 动态码本与新内容分配（工业）**
- 快手 **GR4AD**（arXiv 2602.22732，2026-02，已全量部署、4 亿用户）：传统 ANN 索引依赖 embedding 更新、"索引刷新通常是分钟级"；SID 索引由相对稳定的 content→UA-SID 映射驱动、不需频繁全局重建；**"当一个新 item 到来，我们只需从内容计算其 UA-SID 并在数秒内更新双向索引（UA-SID ↔ Item ID）"**，"显著改善 item 新鲜度与冷启覆盖，并保证训练-服务一致"；低活用户转化率 +7.28% 归因于内容 SID 的泛化与更实时的索引。— [arXiv 2602.22732](https://arxiv.org/abs/2602.22732)；本地全文镜像 `scratchpad/gr4ad.txt`（[A] 全文）。**已上线。**
- 快手 **From a Static Multi-Level Small Semantic Codebook to a Dynamic Single-Level Large Semantic Codebook**（arXiv 2608.21012，2026-08）：多级残差码增加解码成本且层次空间稀疏占用，**静态码本随新 item 到来与曝光分布变化而与当前流量失配**；改为**单层大语义码本 + 单独的协同消歧 token**（减少碰撞），并引入**曝光感知的动态更新：时间权重衰减、EMA 中心更新、对 SID 变更的曝光加权惩罚**（热门 item 的 SID 更难被改动）；离线评测框架覆盖表征质量、码利用率、簇负载、全 SID 碰撞与时间稳定性；OneRec-V1/V2 上 Recall@10 +5.0～8.8% / +7.1～8.7%；解码 FLOPs -47.9～48.7%、单卡 QPS +28.6～47.0%；**五天、2.5% 生产流量 A/B 主消费指标 +0.792%**。— [arXiv 2608.21012](https://arxiv.org/abs/2608.21012)（摘要 [A]）。**已上线并公开收益。**

**(d) "SID + ID 双用"的工业做法**
- **SID-Coord**（arXiv 2604.10471，2026-04，短视频搜索排序）：哈希 ID（HID）擅长记忆高频交互但对低曝光长尾泛化差；**把 SID 作为结构化标识而非辅助稠密特征直接放进 ID 排序模型**，三组件：层次 SID 的注意力融合、**目标感知的 HID–SID 门控**（自适应平衡记忆与泛化）、SID 驱动的兴趣对齐；不改主干即可集成；线上 **搜索长播率 +0.664%、搜索播放时长 +0.369%**。— [arXiv 2604.10471](https://arxiv.org/abs/2604.10471)（摘要 [A]；公司未署名，题名与指标指向短视频平台搜索）。**已上线并公开收益。**
- Meta prefix-ngram（SID 特征成为重要性最高的稀疏特征，与哈希 ID 并存）、字节 TRM（gen-token + BPE mem-token）、Google 双用途 SID（2607.24865）、快手单层码本的协同消歧 token（上文）、FlexCode 的 CF 码本/语义码本双码本（研究）、Netflix 协同 embedding 掩码（[A]）。— 见 06 笔记 KQ3 与本节。

### Inferences
- 对短视频新内容而言，SID 的价值链条是：**内容可算 → 秒级拿到可训练/可检索的离散键 → 与相似 item 共享统计**；它解决的是"新内容能不能被模型表示"，而不是"新内容能不能被生成式模型召回"——后者受 ColdSID/DREAM 指出的 token 可达性限制，需要动态 beam、多候选 SID 或打分式接口补救。
- 碰撞在冷启动上是双刃剑：碰撞组内共享统计正是新 item 获得先验的来源（QuaSID 也把部分碰撞视为良性冗余），因此"把碰撞降到零"并非冷启动最优；更有效的是**按曝光动态更新码本并保护热门 item 的 SID 稳定**（快手 2608.21012 的曝光加权惩罚）。
- 评测必须用 item 级而非 SID 级命中，否则冷启动收益会被高估（2605.25330）；OneMall 的"碰撞降了命中率没涨"也可能部分是评测口径问题。

### Gaps
- 没有公开资料给出"一条新视频从上传到拿到 SID 的端到端时延分布"；GR4AD 的"数秒"是索引更新时延，不含内容理解与 MLLM 推理。
- 快手 2608.21012 动态更新在线上是否全量、SID 变更频率的运行数值未披露；MERGE 线上数字仅有二手转述。
- Meta/Google 的码本在新 item 上的分配策略（是否批量重训、增量分配周期）无公开资料。

## KQ4 冷启动专用模型与链路：为新内容找用户的反向召回、冷启专用排序/校准、冷启 tower/专家、与主模型统一或分离

### Takeaway
2025–2026 公开上线的冷启链路呈"**主模型去偏 + 独立的冷启召回/探索通道**"的双轨结构：Pinterest 把去偏做进全漏斗模型（engagement dropout、显式交叉、分内容类型校准、分数正则）同时维护独立探索语料；阿里 AliBoost 作为"自然推荐的补充"用分层加权与 item 侧出价把高潜冷品快速推给合适用户，半年冷启超 10 亿新品、冷品点击与 GMV +60%；抖音 Next-User Retrieval 用"生成下一个会互动的用户"把冷启变成 item→user 检索（DAU +0.0142%、投稿 +0.1144%）；阿里 FilterLLM 用一次前向输出整个用户分布（比逐用户判断快 34.75 倍、相对 ColdLLM GMV +10.86%）。排序侧的校准手段是**分数正则（Pinterest）、分内容类型的 fresh-aware 校准（PinEqualizer）、伪标签 + 置信度去噪（快手 DIF，已上线）、LLM 先验转 Beta 伪计数（NAVER，仅低曝光段 +9.51% 显著）、动态先验 Thompson（regret 曝光 -21%）**。"冷启 tower/专家"的公开形态是流行度分层的元任务（PAM）、特征域隔离（MESH）、用户组子模块（POSO）、多解码器（OneRec 多解码器新内容冷启 +2.09%），而不是单独的冷启动排序模型。

**(d) 与主模型统一或分离**
- 分离通道：PinEqualizer 的独立探索语料（Thompson/UCB 分配）与"毕业"机制（达到互动阈值进入 exploitation 语料，否则回到探索；[B]）；AliBoost 作为自然推荐的"补充"（[A]）；Google item-level discoverability 分配（06 笔记，[A]）。
- 统一主干：OneRec 技术报告称端到端模型把"冷启与长尾视频投放"作为生态目标统一在奖励系统里（本地全文 [A]），**但 OneRec-V2 报告显示全流量切换后冷启视频观看 -44.7%/-36.7%**（KQ5），说明统一模型仍需独立的冷启保障。
- "创作者侧价值"对链路设计的影响：**Content Exploration Beyond the Feed: Creator Supply and the Shared Corpus**（arXiv 2608.29430，2026-09，"a major short-video platform"）：**在许多短视频平台上，探索是新视频触达观众的主要途径**；八个月的创作者消融显示生产探索使每创作者投稿 +8.55%、至少投稿一次的创作者 +7.10%；预算匹配的重分配提高创作者参与且短期观众侧无可检测变化；**一年期观众侧消融：视频观看 +1.74% 但观看时长 -2.13%**；指出观众侧 A/B 会因两组共享语料而抵消语料效应，三周实验无法判定最终语料效应的符号。— [arXiv 2608.29430](https://arxiv.org/abs/2608.29430)（摘要 [A]）。

### Inferences
- "为新内容找用户"的三条工业路线（序列生成式 Next-User、LLM 一次性分布 FilterLLM、社交/相似扩散 SocRipple）本质都是把冷启从"user→item 打分"改成"item→user 检索"，这样新内容的曝光不依赖它在主模型里的 ID 质量；它们的全站指标都很小（DAU +0.014%），真正的目标是创作者投稿/留存（Next-User Retrieval 的 publications、2608.29430 的创作者供给）。
- 校准类方法的共同点是**用"曝光数"作为置信度的代理**（PinEqualizer 的 N+n、NAVER 的 κ、Pinterest 的冷/非冷分数正则），并且收益只在低曝光段显著（NAVER 10–49 次曝光 +9.51% 而总体不显著）；这意味着冷启排序的 A/B 必须按曝光分桶读数。
- "统一 vs 分离"的证据偏向**分离通道 + 主模型去偏并行**：OneRec-V2 的冷启退化与 Pinterest 的"独立语料 + 全漏斗去偏"互为正反例。

### Gaps
- 抖音 Next-User Retrieval 之外，没有 TikTok/抖音公开的冷启排序/校准方案（"Joint Similar User Exploration and Informative Behavior Guidance for Multi-Modal New Item Recommendation"，2026-04 会议论文仅有题名，见 KQ9）。
- "A Cold-start Recommendation System at Kuaishou"（WWW 2025 Companion）仅从搜索摘要得知题名，内容不可得（[C]）。
- DIF、Soft Curriculum、Representation Curriculum、Tubi 均未公开百分比。

## KQ5 生成式推荐下的冷启动：记忆 vs 泛化、OneRec 系列的冷启指标与补救、SID 对新内容的覆盖速度

### Takeaway
2026 年的三项证据把"生成式推荐天然利于冷启动"的说法拆成两半：(1) **Meta+UCSD 的 "How Well Does Generative Recommendation Generalize?"** 证明 GR 在需要"泛化"的实例上优于 ID 模型（Office 数据 NDCG@10 +58.8%）、ID 模型在"记忆"实例上更强，但 **GR 的 item 级泛化大多可归结为 token 级（前缀 n-gram）记忆**；Snap+KAIST 的研究进一步显示 LLM 型 GR 的收益"绝大多数"来自一跳记忆可预测的用户；(2) 复现研究表明 **item 冷启比 user 冷启难得多（Recall@10 差距常超 20%），扩大模型、RL 微调都不能可靠缩小差距，文本标识帮助 item 冷启但伤 warm**；(3) 最重要的工业数据点是 **OneRec-V2 技术报告自述：全流量切换到 V2 后，快手/极速版冷启视频观看分别 -44.7%/-36.7%、簇密度 +11.7%/+7.9%**，被作者列为"需要在未来方向中慎重考虑的关键挑战"；快手随后的补救出现在多解码器 OneRec（新内容冷启 +2.09%）、动态单层码本（曝光感知更新）、PIT 与 DREAM。SID 对新内容的覆盖速度在公开资料中只有 GR4AD 的"从内容算 SID、数秒更新索引"与 Memory Layer 的"embedding 新鲜度 20 秒"两个点。

### Cited Findings

**(a) 记忆 vs 泛化**
- **How Well Does Generative Recommendation Generalize?**（arXiv 2603.19809，2026-03；作者含 UCSD 的 Julian McAuley、Yupeng Hou、Jingbo Shang 与 Jiacheng Li、Shuai Shao、Wei Shao、Xiaoqiang Luo、Luke Simon 等工业作者）：按正确预测所需能力把测试实例分为"记忆（复用训练中见过的 item 转移）"与"泛化（组合已知模式预测未见转移）"；**GR（TIGER）在泛化子集显著优于 ID 模型（SASRec），例如 Office 数据 NDCG@10 +58.8%；ID 模型在记忆子集更强**；把分析从 item 级下沉到 token 级后发现"**看似 item 级的泛化常常归结为 GR 的 token 级记忆**"（共享语义 token 内的前缀 n-gram 记忆）；两者互补，用最大 softmax 概率作记忆感知指标做逐实例自适应集成，稳定优于单模型与固定权重集成。— [arXiv 2603.19809](https://arxiv.org/abs/2603.19809)（摘要 [A]）；数字 [memgrafter](https://github.com/memgrafter/research-digests/blob/main/ml_research_analysis_2026/2603.19809_how-well-does-generative-recommendation-generalize_20260402_072929.md)（[B]）。**仅研究。**
- **On the Memorization Behavior of LLMs in Generative Recommendation**（arXiv 2606.17276，2026-06，Snap + KAIST）：考察"一跳记忆"（推荐训练数据中直接后继 item）；**LLM 型 GR 比非 LLM 的 GR 更依赖一跳记忆，其对 GR 基线的大部分增益来自目标 item 可由一跳记忆预测的用户**；提出 IIRG 训练策略学习多跳协同关系与主题语义关系，对"测试 item 未被训练期一跳转移覆盖"的用户增益尤其大。— [arXiv 2606.17276](https://arxiv.org/abs/2606.17276)（摘要 [A]）。**仅研究。**
- **Cold-Starts in Generative Recommendation: A Reproducibility Study**（arXiv 2603.29845，2026-03/04）：统一协议复现 TIGER、P5、OneRec 等，在 Amazon-Toys、MicroLens、Steam 上按时间切分 item 冷启（前 90% 交互训练、后 10% 测试）；**item 冷启系统性且大幅低于 user 冷启（Recall@10 差距常 >20%）**；**文本标题标识显著改善 item 冷启但损害 warm 与 user 冷启，OPQ 等组合语义码更平衡**；扩大参数只有边际单调改善，**RL 微调不能一致改善冷启且可能损害鲁棒性**。— [arXiv 2603.29845](https://arxiv.org/abs/2603.29845)（摘要 [A]）；结论细节 [memgrafter](https://github.com/memgrafter/research-digests/blob/main/ml_research_analysis_2026/2603.29845_cold-starts-in-generative-recommendation-a-reproducibility-study_20260405_133818.md)（[B]）。**仅研究。**
- Meta 的 **"From Raw IDs to Semantic Planning"**（arXiv 2607.09540，2026-07，综述/立场）：原始 ID 之所以长期主导是因为可精确查表、可记忆 item 特定模式；SID 把部分内容/上下文/跨域信息封装进"模型面向的身份"；提出"语义规划"——先预测下一次曝光的语义目标再实例化为具体 item 或生成创意。— [arXiv 2607.09540](https://arxiv.org/abs/2607.09540)（摘要 [A]）。
- ColdSID（可组合但不开放）、GenRecEdit（冷启坍缩近零）、DREAM（早期静态分配是瓶颈）见 KQ3(b)。
- Meta Facebook Forum 生成式召回（2609.38646）用 Feed 跨平台数据学 SID 迁移到冷启的 Forum 面（01 笔记，[B]）；GenRank（2505.04180）称冷启 item 改善"尤其显著"（01 笔记，[A]）。

**(b) OneRec 系列的冷启指标与补救（快手，已上线）**
- **OneRec 技术报告**（arXiv 2506.13695，2025-06）：主场景 25% QPS，App Stay Time +0.54%/+1.24%，"同时改善所有核心指标——包括用户互动、**视频冷启**与分发均衡"；在"工业场景对齐"一节把"冷启与长尾视频投放"列为端到端系统需统一处理的生态目标，批评传统级联在单一阶段打补丁导致问题交替复发。— [arXiv 2506.13695](https://arxiv.org/abs/2506.13695)；本地全文 `scratchpad/onerec.txt`（[A] 全文）。
- **OneRec-V2 技术报告**（arXiv 2508.20900，2025-08）：在 5% 实验流量之外，额外开 1% "关闭缓存、全部请求走 OneRec-V2"的对照组（Table 9，相对 OneRec-V1）：快手 App Stay Time +0.405%、Watch Time +0.513%、Video View +0.938%、Like +15.024%、Follow +15.755%、Comment +29.249%、Collect +9.640%、Forward +24.741%，**Cold-Start Video View -44.704%、Cluster Density +11.692%**；极速版 App Stay Time +0.958%、Watch Time +2.456%、Video View -1.121%、Like +12.783%、Follow +21.376%、Comment +16.975%、Collect +12.886%、Forward +30.957%，**Cold-Start Video View -36.730%、Cluster Density +7.933%**；原文："certain ecosystem-level metrics present concerning trends. Notably, cold-start video views experience significant degradation... This presents a critical challenge that requires careful consideration in our future directions"。— [arXiv 2508.20900](https://arxiv.org/abs/2508.20900)；本地全文 `scratchpad/onerec2.txt`（[A] 全文）。**已上线并公开（负向）收益。**
- 补救线索：多解码器 OneRec（2607.26500）新内容冷启 +2.09%（01 笔记，[B]）；动态单层大码本的曝光感知更新（2608.21012，+0.792%，[A]）；PIT 动态个性化 tokenizer（+0.402% App Stay Time，[A]）；DREAM 的多候选 SID + 动态 beam（研究，[A]）；QuaSID/AdaSID 的冷启切片收益（[A]）；快手 Explorer LLM-Rec Challenge 2026（06 笔记）。
- 评测提示：OneRec-V2 的互动指标 +9.6～29.2% 与冷启 -36.7～44.7% 同时出现，与"簇密度上升"一致，表明生成式模型在全流量下会收敛到高互动的头部簇。

**(c) SID 对新内容的覆盖速度（新内容多久拿到 SID / 可被打分）**
- 快手 GR4AD：新 item 到来 → 从内容计算 UA-SID → **数秒内更新双向索引**（[A] 全文）。
- Meta Memory Layer：item embedding 新鲜度 **O(5 min) → O(20 s)**，always-on 属性 embedding 使未缓存 item 也可打分（覆盖率 100%）（[A]/[B]）。
- Meta MPZCH：新 ID 立即获得专属槽位（[B]）。
- 字节 Streaming VQ（2501.08695）：模型更新周期 = dump 周期 5–10 分钟（[C]）；字节 Monolith（2022 背景）：参数分钟级同步到在线 PS（[C] 搜索摘要）。
- 快手动态码本：曝光感知的 EMA 中心更新与 SID 变更惩罚（更新频率未披露，[A]）；TAGR：活跃直播广告 SID "周期性"刷新（周期未披露，[A]）；TikTok FLUID：直播以 2 分钟切片编码、slice 级码即时表示当前内容（06 笔记，[B]）。
- TikTok X-Rec 不用 SID（anchor + 球面流匹配，吞吐 3.46×；06 笔记，[B]）——避开了 SID 分配时延问题，但其对新内容的处理未披露。

### Inferences
- 生成式推荐对新内容的"泛化"实际是**对共享 token 统计的复用**：当新内容的 SID 落在高频前缀上时它受益（这解释了 SID 的冷启切片收益），当它需要新原子 token 或低频路径时它被系统性忽略（这解释了 OneRec-V2 的冷启观看 -44.7% 与簇密度上升）。两者不矛盾，取决于新内容的 SID 分布。
- 因此生成式主链路上的新内容保障要么在 tokenizer 侧（动态码本、多候选 SID、曝光感知更新），要么在解码侧（动态 beam、打分式接口、独立冷启通道）；仅靠奖励系统里的"生态项"（OneRec V1 的表述）不足以抵消全流量下的头部收敛。
- "新内容多久拿到 SID"在公开资料里没有端到端数字，但工程上限由 MLLM 内容理解时延决定（KQ6），而索引/embedding 侧已能做到秒级（GR4AD、Memory Layer）。

### Gaps
- OneRec-V2 冷启视频观看下降的原因分析、后续是否已修复、修复后的数字均未公开；5% 流量常规实验组的冷启指标也未单列。
- 没有平台公开"生成式召回对 <1 小时新内容的覆盖率"；ColdSID/DREAM 全部在公开数据集上。
- Meta 自己的 GR（HSTU/VISTA 系）在新内容上的表现无公开资料（VISTA 摘要只谈长序列）。

## KQ6 LLM/MLLM 用于新内容理解：打标/描述/受众预测的公开方案、成本与延迟、蒸馏到小模型

### Takeaway
公开上线的 MLLM 用法仍是"**离线/异步生成描述或 token，再离散化进模型**"（Meta caption→token、字节 TRM 域内 captioning、快手 RecoReward 用冻结推荐双塔做奖励训练 MLLM 写"对推荐有用"的描述、快手 OneRec miniCPM-V 压成 4 个 token）；2025–2026 新出现的三种"新内容理解"用法是：**(1) 用 LLM 直接预测受众/分布**（阿里 FilterLLM 一次前向输出用户分布，已上线）；**(2) 用 LLM 生成冷启打分器参数**（LLM-HYPER，已上线）；**(3) 用 LLM 做推理式冷启排序或用户模拟**（Netflix 推理微调模型在某些情况下比生产排序模型高 8%；Google 用 LLM 扮演用户生成冷品交互，仅研究）。学术对照实验给出两条反向证据：训练-free 场景下文本 embedding 模型优于 LLM 重排（2512.13001），生成式 LLM embedding 在零样本视频召回中会坍缩、CLIP 更好（Zalando VCG）。成本方面仍无平台公开"每条新视频的 MLLM 推理成本"；唯一外部数据点是学术审计用 Gemini 2.5 Flash（8 帧+文本）标注约 3.7k 条 TikTok 视频总花费约 50 美元（06 笔记）。蒸馏的工业形态是 Rec-Distill（24B→1B）、YouTube→YouTube Music 跨域蒸馏（新发行 +11.39%）与 Keeta SemRaD（把 LLM 结构化语义画像与"事后"推理蒸馏进小学生模型，LTV +1.0%）。

### Cited Findings
- 字节 **TRM**：Qwen2.5-VL 在真实曝光日志上做域内视频 captioning → 末层 mean-pooling → 行为对比对齐 → RQ-Kmeans；<1 天新品 AUC +0.06%、>7 天 +0.11%（06 笔记，[A]/[B]）。

- **Predicting Movie Hits Before They Happen with LLMs**（arXiv 2505.02693，2025-05，"a large entertainment platform"）：用 LLM 基于元数据预测冷启电影的流行度，可接入召回或供编辑团队公平推广。— [arXiv 2505.02693](https://arxiv.org/abs/2505.02693)（摘要 [A]）。**有论文，部署未说明。**
- 阿里 FilterLLM（受众分布预测，上线）、LLM-HYPER（参数生成，上线）、NAVER LLM 先验（Beta 伪计数）、Google LLM 用户模拟（研究）见 KQ2/KQ4。

- 蒸馏：字节 **Rec-Distill**（24B→1B，TikTok Live 礼物收入 +0.78%）、Google **YouTube→YouTube Music 零样本跨域蒸馏**（新发行内容 engagement +11.39%）（06 笔记，[B]）；**SemRaD**（arXiv 2607.17070，2026-07，Keeta，新用户 LTV/CVR）：用"发现-整理-审计"工作流把 LLM 自由推理改成结构化语义画像（Densified Semantic Profile），训练期用"事后"推理目标做 hindsight 蒸馏；大规模工业数据 LTV(Gini) +1.9%、CVR(AUROC) +1.0%；**四周线上 A/B LTV +1.0%、CVR +0.43%**；只用 9% 训练数据即可匹配生产 LTV。— [arXiv 2607.17070](https://arxiv.org/abs/2607.17070)（摘要 [A]）。**已上线并公开收益（用户侧冷启，方法可迁移到内容侧）。**
- 成本数据点：学术审计 Gemini 2.5 Flash 标注约 3.7k TikTok 视频约 50 美元、8 帧+文本成本是原生视频的一半（06 笔记，[A]）；Meta MM-LLM "QPS 持平"；SSRLive 延迟 +1.33%；GateSID <5 ms；SA²CRQ TP99 50 ms。

### Inferences
- 对新内容最"值钱"的 LLM 产物不是自由文本而是**可离散化、可校准的结构化输出**（token/标签/属性/先验计数/线性权重/用户分布）——所有上线案例都如此；自由文本 caption 只作为中间产物再编码。
- 用 LLM 直接做冷启排序（Netflix 推理式）仍停留在"某些情况下优于生产模型"的阶段，且学术对照表明文本 embedding + 判别式模型往往更稳；短视频平台更现实的路径是"MLLM 离线理解 → SID/属性 → 现有排序/召回"。
- 成本控制的通用做法（蒸馏、压缩输入、只覆盖新内容）在 06 笔记已归纳；本节补充的是"LLM 产物进入冷启链路的接口形态"。

### Gaps
- 没有任何平台公开"新内容 MLLM 理解的端到端时延（上传→可被推荐）"与 GPU 成本；RecoReward/TRM/OneRec 的 captioning 吞吐未披露。
- Netflix LLM 推理冷启、"Predicting Movie Hits" 的部署状态未知。

## KQ7 早期反馈融合：前 N 次曝光的反馈如何快速进入模型（在线学习、快速 ID 更新、Bayesian 更新）及其与内容表征的融合

### Takeaway
公开资料把"前 N 次曝光"的利用分成三层：**(1) 参数/索引层的秒级新鲜度**——Meta Memory Layer（embedding 新鲜度 5 分钟→20 秒、冷启互动 +5–6%）、MPZCH（新 ID 专属槽位、新视频曝光 +0.83%）、快手 GR4AD（秒级 SID 索引）、字节 Monolith 分钟级同步（2022 背景）与 Streaming VQ 的 5–10 分钟；**(2) 统计层的贝叶斯/置信度更新**——PinEqualizer 的 (αN+e)/(N+n) 后验与实时曝光 UCB、Google 的"按 item 学习可被发现概率曲线"、NAVER 的 LLM 先验 + Beta 伪计数、Dynamic Prior TS（regret 曝光 -21%）、Meta Epinet；**(3) 模型层的早期反馈序列建模**——抖音 Next-User Retrieval 用最近互动用户序列生成下一个用户、SocRipple 第二阶段用早期互动做 KNN 扩散、快手 DIF 用内容相似 warm item 的伪标签 + 置信度去噪冷品早期噪声反馈、PAM 按流行度阈值切元任务。与内容表征的融合方式是**内容先验 + 行为后验的加权**（先验强度 N/κ 由设计者设定）或**门控**（GateSID 按交互数切换）。创作者侧证据（2608.29430）提醒：早期曝光的价值包含创作者供给（投稿 +8.55%），观众侧短期 A/B 无法度量。

### Cited Findings
- Meta Memory Layer：训练时写回（学习率 1 的 writeback）、服务读同一表；cache miss 时该分量置零、保留可泛化属性 a_i；**新鲜度 O(20 s)**、最新内容召回 >2×、冷启互动 +5–6%（[A]/[B]，KQ2）。
- Meta MPZCH：新 ID 专属槽位、驱逐时重置权重与优化器状态；新视频曝光 +0.83%（[B]，KQ2）。
- 快手 GR4AD：秒级 SID 索引更新（[A]，KQ3）。字节 Monolith（2022）：在线训练参数分钟级同步到服务 PS（[C] 搜索摘要，背景）；字节 Streaming VQ（2501.08695）：实时分配、5–10 分钟更新周期、新品更新机会少（[C]）。
- PinEqualizer：r̂ = (α·N + e)/(N + n)，实时曝光 UCB（Flink 实时特征），Thompson 后验/Neural Linear UCB 分配独立探索语料，达到互动阈值"毕业"（[B]，KQ4）；Google item-level 探索分配：学习每个 item"获得一定探索流量后可被发现的概率"（06 笔记，[A]）。
- NAVER：α = 1 + κp、β = 1 + κ(1−p)，收益在 10–49 次曝光段最大（+9.51%）、总体不显著（[A]/[B]，KQ4）；Dynamic Prior TS：新臂以目标概率 ε 优于最佳臂，regretted impressions -21%（[B]）；Meta Epinet：冷启内容曝光 +17%（[B]，2024 背景）。
- 抖音 Next-User Retrieval：最近互动用户序列（≤50）+ item prefix → 下一个用户；prefix 掩码后 Recall@20 -14.15%（[A]/[B]，KQ4）。SocRipple：早期互动 + 稳定用户 embedding 的 KNN "ripple"（06 笔记，[A]）。
- 快手 DIF：冷品早期反馈更噪（标题党、位置偏差），用内容相似 warm item 推伪标签 + 内容相似度置信度 + 相对熵与冷启状态估计不确定性，样本级纠正；已部署（[A]，KQ4）。
- 快手作者 PAM：流式数据按流行度阈值切任务、低流行度任务加增强与自监督（[B]，KQ1）。
- 阿里 AliBoost：分层 boosting + 潜力预测 + item 侧出价，180 天内冷品点击/GMV +60%（[A]，KQ4）。
- 创作者侧：2608.29430 的八个月创作者消融（投稿 +8.55%、创作者 +7.10%）与一年观众消融（观看 +1.74%、时长 -2.13%）（[A]，KQ4）。
- 快手动态码本：曝光加权的 SID 变更惩罚（热门 item 的 SID 更稳定，新 item 更易被重分配）（[A]，KQ3）。
- 数据工程背景：Meta 把 SID 与 ID 并用后同一 item 预测方差 -43%（06 笔记，[B]）；MIM 的 RIM 窗口消息把新 item 的 MM embedding 同时送训练与服务（[A]，KQ1）。

### Inferences
- "前 N 次曝光"在工业里被三种时钟处理：秒级（embedding/索引写回）、分钟级（参数同步）、小时级（码本/探索语料更新）；短视频平台若只有分钟级参数同步而无秒级 embedding 写回，新内容在首小时内只能依赖内容先验——这正是 Memory Layer 报告"5 分钟内媒体 >2×"的来源。
- 贝叶斯式融合的关键超参是先验强度（N、κ）：NAVER 的结果说明先验过强（Content Prior）会伤总体，先验只在 10–49 次曝光段起作用；设计上应让先验强度随内容置信度（MLLM 质量、相似 warm item 数量）变化，而不是常数。
- 早期反馈的"噪声"问题（DIF）在短视频尤其突出：首批曝光来自探索流量，分布与常规流量不同（POSO 对新用户的"分布不同"论断同样适用于新内容的首批观众）。

### Gaps
- 没有公开资料给出 TikTok/抖音的参数同步周期、新内容 embedding 写回时延；Monolith 为 2022 年数字。
- Google/YouTube 的 discoverability 曲线形状、所需探索曝光数未披露。
- 没有论文量化"前 N 次曝光的反馈 vs 内容先验"的最优混合权重随时间的变化。

- 对 TikTok 规模的平台，最可迁移的组合是：IDProxy 式 proxy 注入（无需改主干）+ Pinterest 式分数正则/残差 + Memory Layer 式秒级写回 + 独立的 item→user 冷启召回（Next-User/FilterLLM）+ 曝光感知码本；每一项都有公开上线先例且代价可控。

### Gaps
- 几乎没有平台公开冷启动的**成本/收益比**（每万次探索曝光的留存收益、GPU 成本）；创作者侧长期价值只有 2608.29430 一篇定量。
- 未来判断为推断，无来源直接支持。

## KQ9 TikTok / 抖音 / 字节跳动公开资料专题（仅公开信息）

### Takeaway
字节系 2025–2026 公开的新内容冷启资料集中在六类：**(1) 反向召回**（抖音 Next-User Retrieval）；**(2) 特征自适应**（AdaF²M² 在抖音集团召回/排序广泛部署，含抖音音乐的冷启双塔）；**(3) 语义 ID/索引**（头条 R3-VAE 冷启 +15.36%、MERGE 流式动态索引、Streaming VQ、抖音 GEAR 冷启广告 +1.46%、TRM 的 <1 天新品分层）；**(4) 去 ID 的多模态表征**（TikTok FLUID 直播，冷启直播间 +2.05%）；**(5) 统一排序主干的冷启副产品**（OneTrans 冷启商品 order/u +13.59%、Rec-Distill、HELIX、X-Rec）；**(6) 会议论文题名**（"Joint Similar User Exploration and Informative Behavior Guidance for Multi-Modal New Item Recommendation"，2026-04）。TikTok 官方页面只描述候选选择→预测→排序→相似性检查→规则的流程，明确"粉丝数与历史爆款不是直接因素"，**没有任何官方来源证实"新视频先投给 200–500 人测试"的说法**（营销/创作者博客数字互相矛盾，均为 C 级）。

### Inferences
- 字节系公开论文的冷启叙事与快手/Pinterest 不同：没有单独的"冷启动系统"论文（除 Next-User Retrieval），冷启收益多作为统一主干（OneTrans/HELIX）、特征自适应（AdaF²M²）或索引（MERGE/Streaming VQ）的副产品披露；这与 TikTok 官方"没有直接的粉丝数因素"的表述一致，即冷启更多依赖内容表征与统一模型的泛化而非显式配额。
