## 1. 货架电商头部平台近一年的推荐/搜索技术变化（阿里、京东、拼多多/Temu、Amazon、Shopee/Lazada、Coupang、Mercado Libre）

### Takeaway
阿里（淘天 + 阿里妈妈 + AIDC/AliExpress）是公开信息最密集的平台：2025 年 7 月起把 LLM 推荐（RecGPT，百亿参数）全量推到手淘"猜你喜欢"，随后 V2/V3 连续迭代并把端到端推理算力砍半；搜索侧把生成式召回（TSGR）、LLM 相关性（LORE/TaoSR1）直接上线；广告侧把多模态、超长序列（10 万）与可扩展 Transformer（EST/LUM）做成了可复现的收益。京东公开的是搜索广告生成式召回（GRAM）与 JD App 的生成式推荐/重排（GenRec、OxygenREC、DEGR）；Coupang 公开了搜索 CVR 模型 8 倍算力 scaling 的工程实践；Amazon 的公开动作集中在购物 Agent（Rufus → Alexa for Shopping、Buy for Me）而非推荐模型论文；拼多多/Temu、Lazada、Mercado Libre 几乎没有可核实的技术公开。

**阿里巴巴 – 淘天（搜索）**
- TSGR "Taobao Search Generative Retrieval"（arXiv 2607.18796, 2026-07）：生成式召回引入价值感知；Query-aware Parallel SID（QP-SID）用 query-item 统计建并行码本；离线 HR@1000 +9.16%；线上 IPV +0.43%、成交笔数 +1.12%、GMV +1.64%，已全量。【B，待核】`[已上线+公开收益]` — [arXiv 2607.18796](https://arxiv.org/abs/2607.18796)
- LORE "A Large Generative Model for Search Relevance"（Alibaba, 技术报告 2025-11-02，arXiv 2512.03025）：三年三轮迭代的 LLM 相关性框架，线上 GoodRate 累计 +27%；通过"按 query 频次分层"的部署策略把离线 LLM 能力迁移到线上，线上 A/B 合计 GoodRate +10%；训练为渐进式 CoT 合成 SFT + RL 偏好对齐，并构建 RAIR 基准。【A】`[已上线+公开收益]` — [arXiv 2512.03025](https://arxiv.org/abs/2512.03025)
- TaoSR1 "The Thinking Model for E-commerce Relevance Search"（淘天, arXiv 2508.12365, v2 2025-10-27）：三阶段（CoT-SFT → 离线 pass@N 采样 + DPO → 难度动态采样 + GRPO），直接把生成式 LLM 部署到线上做相关性，用 post-CoT 处理与基于累计概率的相关性分层降低部署开销；对比基线含 Qwen3-30B-A3B（总参数 30B、激活 3B）；线上 side-by-side 人工评估显著提升。【A】`[已上线+公开收益（人评，无 GMV）]` — [arXiv 2508.12365](https://arxiv.org/abs/2508.12365)

**阿里巴巴 – 阿里妈妈（广告，淘宝展示广告）**
- MIM（arXiv 2502.00321, 2025-02）：多模态内容兴趣建模（预训练 → 内容兴趣感知 SFT → CiUBM），针对冷启动/长尾；在淘宝线上三次发布累计 CTR +14.14%、RPM +4.12%；最终部署版本单次 +3.5% CTR、+1.5% RPM。【A】`[已上线+公开收益]` — [arXiv 2502.00321](https://arxiv.org/abs/2502.00321)
- MUSE（arXiv 2512.07216, 2025-12-08）：多模态搜索式终身兴趣建模（GSU 用余弦相似即可，ESU 需要更丰富的多模态序列建模），2025 年中起部署于淘宝展示广告，支持 10 万长度行为序列，线上延迟开销可忽略，并开源超长序列 + 多模态 embedding 数据集。【A】`[已上线+公开收益（未给具体数字）]` — [arXiv 2512.07216](https://arxiv.org/abs/2512.07216)
- EST（arXiv 2602.10811, 2026-02-11）：把所有原始输入放进单一序列的"完全统一建模" CTR Transformer（Lightweight Cross-Attention + Content Sparse Attention），呈现幂律 scaling；部署于淘宝展示广告：RPM +3.27%、CTR +1.22%。【A】`[已上线+公开收益]` — [arXiv 2602.10811](https://arxiv.org/abs/2602.10811)
- MAL 多归因学习 CVR（CIKM 2025, arXiv 2508.15217）：用多种归因口径的标签联合训练；淘宝展示广告 2025-05-21~25 A/B：GMV +2.7%、订单 +1.2%、ROI +2.6%。【A】`[已上线+公开收益]` — [arXiv 2508.15217](https://arxiv.org/abs/2508.15217)

**阿里巴巴 – AIDC / AliExpress**

- 阿里的路线是"三条线并进"：(1) 推荐主场景用 LLM（RecGPT）直接上线并持续压缩算力；(2) 召回/重排用生成式但工程上走近线/离线预计算（TBGRecall、LUM 的三步范式）规避在线自回归延迟；(3) 判别式排序继续靠 Transformer scaling（EST、SORT、GPSD）拿确定性 GMV。三条线共同的工程前提是 <30 ms 排序 / <100 ms 全链路的延迟预算。

- 拼多多/Temu、Lazada 的"黑盒"状态本身是信号：无法用公开论文推断其技术水平，只能通过产品行为观察。

## 2. 内容电商与直播电商：抖音电商/TikTok Shop、快手电商的公开技术

## 3. 搜推一体化与语义 ID 在电商的应用

### Takeaway
"一个模型同时服务搜索与推荐"在 2025–2026 年主要以三种形态落地：(a) 同一骨干架构在推荐/广告/搜索三类场景分别训练部署（字节 RankMixer、OneTrans）；(b) 搜索与推荐各自端到端生成式化但共享语义 ID 与基础设施（快手 OneRec + OneSearch、淘宝 RecGPT + TSGR）；(c) 真正的单模型联合建模目前多为研究（快手 GenSAR、Amazon SynerGen、IntSR）。语义 ID 在电商已出现多种工业变体：query 感知并行 SID（淘宝 TSGR）、关键词增强分层量化（快手 OneSearch KHQE）、统一广告 SID（快手 GR4AD UA-SID）、LLM 生成的共享文本码（京东 GRAM）、直播动态 SID（SSRLive）。

### Cited Findings
- GenSAR "Unified Generative Search and Recommendation"（Kuaishou 实习合作，arXiv 2504.05730, 2025-04）：指出搜推联合建模存在"此消彼长"的 trade-off（搜索重语义相关、推荐重协同信号）；设计双用途标识符与任务定制训练，用 T5-small 骨干同时服务两任务；在公开与商业数据集上验证。【A】`[仅研究]` — [arXiv 2504.05730](https://arxiv.org/abs/2504.05730)
- SynerGen（Amazon, arXiv 2509.21777）：统一搜索与推荐的上下文化生成式推荐器，预印本无线上结果。【A】`[仅研究]` — [arXiv 2509.21777](https://arxiv.org/abs/2509.21777)
- IntSR（arXiv 2509.21179, 2025-09）：搜索与推荐一体化的生成式框架（题名；所属公司未核实）。【B】 — [arXiv 2509.21179](https://arxiv.org/abs/2509.21179)
- OneTrans-V2（arXiv 2609.28589, 2026-09）：用一个 Transformer 统一召回、粗排、精排（题名；推测为字节 OneTrans 系列延续，未核实）。【B】 — [arXiv 2609.28589](https://arxiv.org/abs/2609.28589)
- RankMixer 在推荐（1B）、广告（1B）、搜索（300M）三类排序场景用同一架构验证并上线。【A】 — [arXiv 2507.15551](https://arxiv.org/abs/2507.15551)
- OneSearch 用 KHQE（关键词增强分层量化编码）生成 item SID，Transformer encoder-decoder（BART/mT5/Qwen3 等）把 query + 用户行为直接映射到 item SID，统一召回/粗排/精排。【B】 — [arXiv 2509.03236](https://arxiv.org/abs/2509.03236)
- TSGR 的 QP-SID 把 query 条件下的价值排序编入 SID 构造（由 query-item 统计派生的并行码本）。【B】 — [arXiv 2607.18796](https://arxiv.org/abs/2607.18796)
- GR4AD 的 UA-SID（Unified Advertisement Semantic ID）用于承载复杂商业信息，并配合 LazyAR 与动态 beam 控制推理成本。【A】 — [arXiv 2602.22732](https://arxiv.org/abs/2602.22732)
- GRAM（京东）明确放弃"从零建语义 ID 体系"，改用 LLM 对 query 与商品联合生成共享文本标识码，理由是语义 ID 丢失 LLM 世界知识、而商品词集与 query 分布不一致。【A】 — [arXiv 2504.01403](https://arxiv.org/abs/2504.01403)
- OpenOneRec 用分层向量量化的 "itemic tokens" 让 LLM 把 item 当作一种模态，并开源 tokenizer。【A】 — [GitHub OpenOneRec](https://github.com/Kuaishou-OneRec/OpenOneRec)
- 2025–2026 其他语义 ID 论文（题名）：FORGE "Forming Semantic Identifiers for Generative Retrieval in Industrial Datasets"（arXiv 2509.20904）；"End-to-End Semantic ID Generation for Generative Advertisement Recommendation"（2602.10445）；"What Makes a Good Semantic ID for Generative Recommendation? A Reproducibility Study"（2609.24430）；"From Interests to Semantic IDs: Retrieval-Grounded Credit Assignment"（2609.29983）；RQ-GMM 多模态语义离散化用于 CTR（2602.12593）；"Efficient Generative Retrieval for E-commerce Search with ..."（2605.14434）。【B】 — [FORGE](https://arxiv.org/abs/2509.20904)；[2602.10445](https://arxiv.org/abs/2602.10445)；[2609.24430](https://arxiv.org/abs/2609.24430)

### Inferences
- 真正"一个模型同时服务搜推"的线上证据仍然缺失；工业上更现实的路径是统一骨干 + 统一 tokenizer/语义 ID + 共享特征/KV 基础设施，各场景分别训练。
- 电商语义 ID 的分歧点在于是否把"价值"（GMV/出价）编入 ID（TSGR、UA-SID）以及是否用 LLM 文本码替代量化 ID（GRAM）；前者更适合平台内闭环，后者更依赖 LLM 世界知识。
- 对内容电商平台，短视频/直播的语义 ID 需要随时间变化（LARM 30 秒刷新、SSRLive 动态 SID），这是与货架电商静态商品 ID 最大的差异。

### Gaps
- IntSR、OneTrans-V2、FORGE 等论文的公司归属与线上状态未核实。
- 没有找到任何平台公开"搜索与推荐共用一套 embedding 服务/特征平台"的架构文章（2025–2026）。

## 4. LLM 与多模态在商品理解中的工业用法（属性抽取、商品 embedding、图文视频表征、评论、知识图谱替代、推理成本）

### Takeaway
商品理解正在从"多任务判别式双塔"转向"生成式 MLLM 统一表征"（阿里 MOON、京东 Oxygen AIIC），LLM 已被用来自动撰写/复查商品信息（淘天商品库 Agent）并做在线相关性判断（LORE、TaoSR1 直接部署 30B-A3B MoE）；推理成本控制的主流做法是离线/近线批量生成 + 在线轻量模型或缓存（LUM、TBGRecall、HCMRM、LORE 的 query 频次分层），以及专门的并行解码/紧凑模型（属性抽取成本 −92%）。

### Cited Findings
- MOON（Alibaba, WSDM 2026, arXiv 2508.11999）：首个生成式 MLLM 商品表征模型（guided MoE 做多模态/aspect 建模、检测商品图核心语义区域抑制背景噪声、专门负采样），发布大规模多模态基准 MBE（含用户购买行为），在跨模态检索、商品分类、属性预测上零样本表现良好；摘要未声明线上部署。【A】`[有论文未确认上线]` — [arXiv 2508.11999](https://arxiv.org/abs/2508.11999)
- JD Oxygen AI Item Center V1（arXiv 2606.28070, 2026-06）：工业级以 LLM/VLM 为中心的商品理解、管理与应用方案（题名/摘要要点）。【B】`[有论文未确认上线细节]` — [arXiv 2606.28070](https://arxiv.org/abs/2606.28070)
- 淘天：用独立 AI Agent 自动学习、撰写商品信息并完成复查，使"多年未解决"的商品库难题数月内显著改善。【B】 — [腾讯新闻 2025-10-18](https://news.qq.com/rain/a/20251018A01L1G00)
- "Scaling E-Commerce Attribute Extraction with Parallel Decoding"（arXiv 2609.09716, 2026-09）：两阶段管线——先为每个类目发现紧凑的"影响购买"属性 schema，再用微调紧凑 LLM + Hyper-Parallel Decoding 抽取值；85% 抽取准确率，推理成本比基础大模型降低 92%。【B】 — [arXiv 2609.09716](https://arxiv.org/abs/2609.09716)
- 其他 2026 年属性抽取/知识图谱论文（题名）：SynthAVE（LLM-Arena 验证的合成标注，2607.07469）；"Beyond Exact Match: 评测方法比模型选择更重要"（2607.22949）；AutoPKG 动态商品-属性知识图谱自动构建（2604.16950）；AI-PAVE-Br 巴西电商属性抽取（2606.24655）；属性感知的受控商品文案生成（2601.04200）。【B】 — [SynthAVE](https://arxiv.org/abs/2607.07469)；[AutoPKG](https://arxiv.org/abs/2604.16950)
- MIM：多模态 embedding 先域内预训练、再用用户行为做内容兴趣对齐 SFT，再与 ID 协同信号融合；明确以冷启动/长尾为动机，线上累计 CTR +14.14%。【A】 — [arXiv 2502.00321](https://arxiv.org/abs/2502.00321)
- MUSE：高质量多模态 embedding + 余弦相似即可胜任 10 万序列的粗筛（GSU），精排单元需要多模态序列建模与 ID 融合。【A】 — [arXiv 2512.07216](https://arxiv.org/abs/2512.07216)
- URM：多模态融合模块做 item 表征；推荐结果对文本输入高度敏感，提示工程可优化工业推荐。【A】 — [arXiv 2502.03041](https://arxiv.org/abs/2502.03041)
- LORE 把相关性拆解为"知识与推理、多模态匹配、规则遵循"三种能力并分别训练；部署用 query 频次分层：高频 query 离线 LLM 打分、长尾在线。【A】 — [arXiv 2512.03025](https://arxiv.org/abs/2512.03025)
- TaoSR1 直接在线部署生成式 LLM（对比含 Qwen3-30B-A3B），用 post-CoT 处理与累计概率分层压缩推理。【A】 — [arXiv 2508.12365](https://arxiv.org/abs/2508.12365)
- LARM：多模态 LLM 在直播数据上微调，每 30 秒生成直播语义 embedding，量化成语义码进入召回/排序。【A】 — [arXiv 2504.05217](https://arxiv.org/abs/2504.05217)
- HCMRM：线上是轻量多模态相关性模型，大型视觉语言教师（数亿短视频预训练）离线蒸馏。【A】 — [ACM DOI](https://doi.org/10.1145/3701716.3715231)
- LUM：第 1、2 步（生成式理解）离线预计算并存储，第 3 步在线 DLRM 读取，满足 <30 ms；RecGPT-V3 把端到端服务算力减少 52.4%。【A / B】 — [arXiv 2502.08309](https://arxiv.org/abs/2502.08309)；[arXiv 2607.15591](https://arxiv.org/abs/2607.15591)
- TBGRecall：近线框架由用户实时行为异步触发生成式推理，在线只做 ANN 读取；训练用"少量历史预训练 + 随机部分增量训练"，强调数据新鲜度优于数据量，GPU 资源仅为原来十分之一。【A】 — [arXiv 2508.11977](https://arxiv.org/abs/2508.11977)
- Shopee Compass-v2：面向东南亚语言与电商的自研 MoE LLM 作为搜推下游的基础模型。【B】 — [arXiv 2504.15527](https://arxiv.org/abs/2504.15527)

### Inferences
- "商品知识图谱被 LLM 替代"在公开资料中表现为两种形态：LLM 直接生成/复查商品结构化信息（淘天商品库 Agent、属性抽取管线），以及 LLM 生成的文本码替代人工本体 ID（京东 GRAM）；完全废弃 KG 的公开案例没有找到，AutoPKG 一类工作反而是"用 LLM 自动建 KG"。

- 评论理解与视频商品表征在 2025–2026 没有找到电商平台的专门工业论文，属于公开信息的空白。

- 属性抽取并行解码论文（2609.09716）的所属公司未核实。
- 没有找到评论理解、视频商品表征、商品 embedding 在线更新成本的量化公开数据。

## 5. Agent 化购物与 agentic commerce：协议、平台动作与对推荐系统的含义（含 TikTok Shop）

### Takeaway
2025-09 到 2026-10 形成了三套开放协议：OpenAI+Stripe 的 ACP（结账/委托支付，后扩展到商品 feed、购物车、发现文档、意图追踪、联盟归因、建议价格）、Google 的 AP2（支付授权层：意图/购物车/支付 mandate，2026-04 发布 v0.2 含"人不在场"流程）与 UCP（Google+Shopify 主导的商务能力层，含目录搜索能力和 MCP 绑定，治理委员会已纳入 Stripe、Amazon、Meta、Microsoft 等）。平台行为分化：OpenAI 在 2026-03 停掉 ChatGPT 内的 Instant Checkout 转向"零售商在 ChatGPT 内建 app"，Amazon 起诉并一度禁止 Perplexity 的购物 agent，TikTok 2026-10-05 推出 Shopping Assistant（对话式 agent）与 Buy Direct（Feed 内一键结账）。对推荐系统的直接含义：商品目录和价格要以结构化 feed/可查询接口暴露给外部 agent，排序要区分"人"与"agent"流量，并承接新的信号（意图追踪、建议价格来源、联盟归因）。

- 推荐系统是否要对 agent 暴露接口：UCP 已把"目录搜索"标准化、并把"个性化交叉/追加销售模块"列入路线图，意味着平台需要一个"面向 agent 的召回+排序 API"（输入 query/intent/context，输出结构化商品与变体），其排序目标更接近搜索相关性 + 价值，而非信息流的停留时长。

## 6. 电商多目标排序与融合、营销（券/补贴）与推荐的联合优化、增量建模

### Takeaway
多目标在 2025–2026 的新进展集中在"生成式/列表级"而非 MMoE 式的进一步改良：淘宝 SORT-Gen 用生成式重排直接优化列表级点击/转化/GMV（GMV +8.10%），快手 GR4AD 用价值感知监督 + 列表级 RL（RSPO）把广告收入目标嵌入生成式模型，OneRec-V2 用真实反馈的策略优化声称多目标无跷跷板；营销与推荐的联合优化公开的是"归因口径联合训练"（淘宝 MAL：GMV +2.7%/ROI +2.6%）和券分配的约束优化/漏斗感知 uplift（SACO、FunnelCausalNet），阿里妈妈"货品全站推"是最大的业务级案例但只有媒体口径。

### Cited Findings
- SORT-Gen（淘宝）：用 Transformer + 有序回归估计变长子列表的多目标价值，Mask-Driven 快速生成算法把多目标候选队列、选择与多样性机制合入推理；"百亿补贴"小程序 CLCK +4.13%、GMV +8.10%，端到端 19 ms。【A】 — [arXiv 2505.07197](https://arxiv.org/abs/2505.07197)
- GR4AD：VSL（Value-Aware Supervised Learning）与 RSPO（Ranking-Guided Softmax Preference Optimization）在列表级指标下优化价值奖励并持续在线更新，收入最高 +4.2%。【A】 — [arXiv 2602.22732](https://arxiv.org/abs/2602.22732)
- OneRec-V2：用真实用户反馈做偏好对齐，报告在提升停留时长同时"平衡多目标且无跷跷板效应"。【A】 — [arXiv 2508.20900](https://arxiv.org/abs/2508.20900)
- RecGPT 的收益按用户/商家/平台三方分别报告（CICD、DT；CTR、IPV、DCAU）。【B】 — [arXiv 2507.22879](https://arxiv.org/abs/2507.22879)
- MAL（淘宝展示广告）：把 First-Click/Last-Click/Linear/数据驱动多触点等归因标签联合学习，主预测器仍对齐系统口径（Last-Click CVR）；线上 GMV +2.7%、订单 +1.2%、ROI +2.6%。【A】 — [arXiv 2508.15217](https://arxiv.org/abs/2508.15217)
- UniROM（美团, arXiv 2505.19755, 2025-05）：用一个端到端生成式模型替代广告多级级联，显式建模广告外部性与激励相容（IC）约束，预训练 + RL 后训练；线上 A/B（2024-11-18~24）CTR +5.2%、RPM +13.6%、广告主 ROI +3.1%。【A】（非电商，但是"单模型多目标含平台收入/广告主 ROI"的参照） — [arXiv 2505.19755](https://arxiv.org/abs/2505.19755)
- MTGR（美团, arXiv 2505.18654）：HSTU 架构保留 DLRM 交叉特征，单样本前向 65 倍 FLOPs，转化量 +1.22%、CTR +1.31%，训练成本不变、推理成本 −12%，已承担外卖主流量。【A】 — [arXiv 2505.18654](https://arxiv.org/abs/2505.18654)
- 券分配：SACO "Sequence-Aware Constrained Optimization Framework for Coupon Distribution in E-commerce"（AAAI 2026, arXiv 2508.09198）；FunnelCausalNet "Funnel-aware Joint Conversion-Revenue Uplift for Multi-tier Coupon Allocation"（arXiv 2608.11675, 2026-08）；UniMVT "Jointly Optimizing Debiased CTR and Uplift for Coupons Marketing"（arXiv 2602.12972, 2026-02）；搜索摘要提到某系统已部署于直播直接响应券位。【B，部署归属待核】 — [SACO](https://arxiv.org/abs/2508.09198)；[FunnelCausalNet](https://arxiv.org/abs/2608.11675)；[UniMVT](https://arxiv.org/abs/2602.12972)
- 增量/预算约束的历史基线（背景）："End-to-End Cost-Effective Incentive Recommendation under Budget Constraint with Uplift Modeling"（2024-08）。【B】 — [arXiv 2408.11623](https://arxiv.org/abs/2408.11623)
- 阿里妈妈：LMA2 与"货品全站推"（全站推广升级）在 2025 双 11 助力百万商品成交 +30%。【C】 — [腾讯新闻 2025-11-11](https://news.qq.com/rain/a/20251111A06CYP00)
- 京东 JD-BP：自动出价与定价的联合决策生成式框架（题名）。【B】 — [arXiv 2604.05845](https://arxiv.org/abs/2604.05845)

### Inferences
- 生成式模型让"多目标融合公式"退化成训练目标的一部分（VSL/RSPO、列表级有序回归），人工融合权重的作用在下降；但所有公开案例仍保留了与系统口径一致的主目标（Last-Click CVR、收入），说明"可解释、可对账"的约束没有消失。

### Gaps
- 未找到 2025–2026 任何平台公开的 CTR/CVR/GMV/利润/留存/商家生态**多目标融合公式或权重机制**的工程文章。

## 7. 冷启动与长尾商家扶持、合规与反作弊对推荐的影响（简要）

### Takeaway
公开资料里冷启动/长尾的主流解法是多模态内容表征替代纯 ID（淘宝 MIM、MUSE、URM、OneRec 的 itemic tokens），没有找到专门的"长尾商家扶持"算法论文；合规与反作弊在 2025–2026 的新变量来自 agent：协议层把授权/问责（AP2 mandates）、agent 身份（UCP `ucp-agent`、Visa Trusted Agent）、营销同意（ACP marketing consent）与隐私最小化（intent traces 只发给相关商家）写入规范，而 Amazon–Perplexity 案把"用户授权 ≠ 平台授权"变成了法律争点。

### Cited Findings
- MIM 明确以冷启动与长尾为动机，用多模态内容兴趣替代 ID 依赖，线上 CTR 累计 +14.14%。【A】 — [arXiv 2502.00321](https://arxiv.org/abs/2502.00321)
- MUSE 指出 ID 特征"在长尾 item 上泛化差、语义表达有限"，用多模态 embedding 做 10 万序列的检索与建模。【A】 — [arXiv 2512.07216](https://arxiv.org/abs/2512.07216)

- 快手 "Awakening Dormant Users: Generative Recommendation with Counterfactual Functional Role Reasoning"（arXiv 2602.13134, 2026-02）：面向沉默用户的生成式推荐（题名）。【B】 — [arXiv 2602.13134](https://arxiv.org/abs/2602.13134)

## 8. 未来 12 个月（2026-10 → 2027-10）的判断：最可能的重点投入与工程瓶颈

### Takeaway
基于上述公开证据，最可能的投入集中在：(1) 生成式推荐/搜索从"单场景试点"走向"推荐+搜索+广告全覆盖"并持续压缩算力（RecGPT-V3 −52%、OneRec-V2 −94% 的路线会被复制）；(2) 语义 ID 与价值/实时性的结合（query 感知 SID、广告 SID、直播动态 SID）；(3) 超长序列（2 万–10 万）+ 蒸馏成为排序标配；(4) 多模态商品/直播理解作为所有模型的共享底座；(5) 面向 agent 的目录/推荐接口与 agent 流量治理。工程瓶颈是延迟预算（排序 <30 ms、生成式 <100 ms）、MFU、在线 RL 的稳定性、以及实时（直播/库存/价格）信号进入生成式模型的通路。

### Cited Findings
- 算力压缩路线已被三家验证：RecGPT-V3 端到端服务算力 −52.4%；OneRec-V2 总计算 −94%；GR4AD 在 L20 上 <100 ms、500+ QPS 并用动态 beam 应对流量波动。【B/A】 — [arXiv 2607.15591](https://arxiv.org/abs/2607.15591)；[arXiv 2508.20900](https://arxiv.org/abs/2508.20900)；[arXiv 2602.22732](https://arxiv.org/abs/2602.22732)
- 排序侧 scaling 的工程边界：LUM 给出 <30 ms、约 100 候选的硬约束与 E2E-GR 在该约束下只能用 64 长度序列；RankMixer 把 MFU 从 4.5% 提到 45%；OneTrans 承认超过当前规模后受在线效率约束。【A】 — [arXiv 2502.08309](https://arxiv.org/abs/2502.08309)；[arXiv 2507.15551](https://arxiv.org/abs/2507.15551)；[arXiv 2510.26104](https://arxiv.org/abs/2510.26104)
- 超长序列与蒸馏：TM20K（5K→20K，延迟 +5.6%）、MUSE（10 万，延迟可忽略）、Rec-Distill（教师 24B/20K，迁移率 >60%）、STCA（10k 全量）。【A】 — [arXiv 2608.07055](https://arxiv.org/abs/2608.07055)；[arXiv 2512.07216](https://arxiv.org/abs/2512.07216)；[arXiv 2605.29755](https://arxiv.org/abs/2605.29755)；[arXiv 2511.06077](https://arxiv.org/abs/2511.06077)
- 实时性：LARM 每 30 秒刷新直播语义；TBGRecall 用近线异步推理把生成式召回与请求解耦并强调数据新鲜度优于数据量。【A】 — [arXiv 2504.05217](https://arxiv.org/abs/2504.05217)；[arXiv 2508.11977](https://arxiv.org/abs/2508.11977)
- 在线 RL 与偏好对齐已进入生产（OneRec-V2 的 GBPO、GR4AD 的 RSPO 持续在线更新、TaoSR1 的 GRPO、LORE 的 RL 对齐）。【A】 — [arXiv 2508.20900](https://arxiv.org/abs/2508.20900)；[arXiv 2602.22732](https://arxiv.org/abs/2602.22732)；[arXiv 2508.12365](https://arxiv.org/abs/2508.12365)
- Agent 面：UCP 路线图把"原生交叉/追加销售（个性化推荐）模块"列为下一步；ACP 未发布变更包含 feed 版本/价格来源；TikTok 已推出 Shopping Assistant 与 Buy Direct（测试中）。【A/B】 — [UCP roadmap](https://github.com/Universal-Commerce-Protocol/ucp/blob/main/docs/documentation/roadmap.md)；[ACP unreleased](https://github.com/agentic-commerce-protocol/agentic-commerce-protocol/tree/main/changelog/unreleased)；[PYMNTS](https://www.pymnts.com/commerce/social-commerce/2026/tiktok-kicks-off-agentic-commerce-push-with-ai-shopping-assistant/)
- 开源基础模型：OpenOneRec 1.7B/8B 与 RecIF-Bench（含商品域）于 2026-01 开源，降低了生成式推荐的进入门槛。【A】 — [GitHub OpenOneRec](https://github.com/Kuaishou-OneRec/OpenOneRec)

### Inferences
- 对内容电商（TikTok Shop/抖音电商）最可能的 12 个月重点：直播与短视频的实时语义（分钟级以内）进入生成式/排序模型；电商广告与商城推荐共享 2 万+ 长度的电商行为序列；Feeds 与 Mall 统一骨干（OneTrans 式）扩展到更多电商子场景；为 Shopping Assistant/Buy Direct 建设"意图→商品"的对话式召回与外部商家目录的理解/同步。
- 最硬的工程瓶颈：(a) 延迟预算下的生成式推理（beam/缓存/lazy decoder 的组合）；(b) 训练侧流式更新与 KV/用户表征缓存的一致性（LUM 指出排序模型参数实时更新导致中间结果不能跨请求共享）；(c) 价格/库存/直播状态等高频变化信号如何进入以语义 ID 为输入的生成式模型（目前只有 LARM 的 30 秒语义与 SSRLive 的动态 SID 两条公开线索）；(d) agent 流量的识别、评估与归因（协议刚起步，平台内尚无公开实践）。
- 不确定性最大的方向：外部 agent 结账是否会在 2027 年前成为可观流量（OpenAI 的回撤 vs. Google/UCP 的持续扩张 vs. Amazon 的封闭）；在没有流量证据前，平台更可能先投入"对内 agent"（自家购物助手）而非对外接口。
