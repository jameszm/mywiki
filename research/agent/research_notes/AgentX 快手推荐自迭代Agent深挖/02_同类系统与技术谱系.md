## 关键问题 1：2026 年"推荐系统自主迭代"同行系统各自的具体设计

### Takeaway
2026 年 2 月至 9 月间，Google（YouTube）、快手、腾讯、网易、阿里、Meta 至少发布了 8 篇"LLM Agent 自主迭代工业推荐模型"的工业论文；它们在**自主边界**上分成两派——AgentX / Google Self-Evolving / RecEvolve 让 Agent 直接驱动线上 A/B 并以 guardrail 否决为闸门，而 RecSys Factory（腾讯）与 AutoLR（网易）明确把 A/B 准入与全量评审保留给人，AutoLR 还首次公开指出"KEEP 棘轮"会把噪声累积成伪进展。

### Cited Findings

#### 1a. AgentX（快手，arXiv 2606.26859，2026-06-25 提交，已有 v2）
- 标题 "AgentX: Towards Agent-Driven Self-Iteration of Industrial Recommender Systems"，2026-06-25 提交；作者（按字母序，搜索片段截断）含 Changxin Lao, Fei Pan, Guozhuang Ma, Han Li, Huihuang Lin, Jijun Shi, Kangzhi Zhao, **Kun Gai**, Mo Zhou, Qinqin Zhou, Quan Chen, Ruochen Yang, Shifu Bie, Shijie Yi, Shuang Yang, Shuo Yang, Wenhao Li, Wentao Xie, Xiao Lv, Xuming Wang, Yijun Wang, Yiming Chen, Yusheng Huang, Zhongyuan (Wang)… — [arXiv 2606.26859](https://arxiv.org/abs/2606.26859)
- 系统目标："not to let a LLM accomplish one-off ML tasks within a sandbox, but to continuously drive algorithmic iteration in real recommendation business"；形成 idea 生成 → 代码/pipeline 开发 → A/B 分析反馈 → 下一轮推演 的完整线上闭环 — [arXiv HTML v2](https://arxiv.org/html/2606.26859v2)
- 三 Agent + 一层：**Brainstorm Agent** 综合历史实验、系统架构、数据分析与外部研究产出排序后的可执行提案；**Developing Agent** 做 repository-grounded 代码生成与多维可靠性验证；**Evaluation Agent** 负责安全上线、流量分配、"guardrail-vetoed A/B judgment"，并把成功与失败都转化为结构化知识资产；**Harness Evolution 层（SGPO）** 把执行轨迹蒸馏为"semantic gradient"更新 — [alphaXiv overview](https://www.alphaxiv.org/overview/2606.26859)
- 动作空间分两条轨道：**online strategy track** 产物是生产代码变更（feature/strategy 级提案，写 C++ 排序逻辑或 DSL 配置）；**offline model track** 产物是训练实验（模型结构提案） — [arXiv HTML v2](https://arxiv.org/html/2606.26859v2)；[二手] [知乎：AgentX 三周 374 个 idea](https://zhuanlan.zhihu.com/p/2055238872141920128)
- 编码失败归因：DSL wiring（CA，35%）、MaTX/C++ 约束（CB，20%）、if/else 结构（CC，15%）三类"框架语法违规"吸收了 70% 的编码失败 — [arXiv HTML v2](https://arxiv.org/html/2606.26859v2)
- 线上判决规则：仅当主目标达显著且无 guardrail 指标（系统稳定性、长期用户体验等）受损时才判 "KEEP"；Evaluation Agent 决定 keep / rollback / 作为负面教训回灌下一轮，把"noisy, delayed, partially observable"的线上流量转为可信奖励信号 — [alphaXiv overview](https://www.alphaxiv.org/overview/2606.26859)
- [二手] 人工环节：通过检查的候选进入人工审核，审核者可 approve / revise / defer / reject；Evaluation Agent 还做参数冲突检查、分桶、指标读取 — [网易订阅转载《快手AgentX：推荐系统开始自我迭代》](https://www.163.com/dy/article/L0ODHU2I0511AQHO.html)；[腾讯新闻 2026-07-01](https://news.qq.com/rain/a/20260701A03IQG00)
- SGPO 定义：把对轨迹失败的自然语言诊断当作"semantic gradients"，只修改单个 subagent 的 spec（指令、验证规则、输出契约、工具使用纪律），其余部分冻结，且仅通过 paired replay 才准入 — [RobustSGPO 2609.09646](https://arxiv.org/html/2609.09646)
- [厂商自述] 结果：三周、3 个 worker、主站 feed + 本地生活商业化两个场景，374 个 idea → 10 个可全量上线；单 worker 并发约 12 个实验 vs 工程师约 1.5（8×）；单 worker 每周 1.1 个可发布结果（为人工的 13.8×）；单位人力业务价值 3.7×；主站 App 消费时长累计 +0.561%；本地生活年化收入 >1 亿元人民币；单 worker 吞吐"每周翻倍" — [alphaXiv overview](https://www.alphaxiv.org/overview/2606.26859)；[二手][知乎](https://zhuanlan.zhihu.com/p/2055238872141920128)；[二手][智东西 X 帖](https://x.com/Chinazhidx/status/2072995747864465756)
- 中文媒体覆盖：腾讯新闻（2026-07-01）、搜狐、网易、知乎两篇（其中一篇标题"推荐算法离失业还有多久？"） — [知乎：快手-AgentX 推荐系统研发自迭代](https://zhuanlan.zhihu.com/p/2054229279240611073)；[搜狐](https://m.sohu.com/a/1044094449_129720)

#### 1b. AgentX-Model（快手后续，arXiv 2609.30001，2026-09-24）
- "Advancing Model Research in AgentX: Long-Horizon Autonomy for Industrial Recommender Systems"，2026-09-24 提交；提出 AgentX-Model：双 Agent（**Research Agent** 从论文与实验发现产出独立评审的提案；**Model Agent** 多轮调查并返回代码、测量与未决问题），在"由业务输入与预测任务定义的 sandbox"内连接提案与模型实验 — [arXiv 2609.30001](https://arxiv.org/abs/2609.30001)
- [厂商自述] 离线 636 个 model-changing 实验；构建 473 节点、6 环境的 dependency-aware 历史回放基准；最新 5 个线上 A/B：获客效率 +10–15%、目标人群广告消耗 +15–20%、观看时长 +0.3–0.8%；回放结论：当 Agent 已能分析并选出具体候选时，更复杂的调度策略**没有一致的效率增益** — [arXiv HTML 2609.30001](https://arxiv.org/html/2609.30001)
- [独立] 批评（GitHub research-issues #1749）：标题性结论"560/636 实验高于业务 AUC 基线"被作者自己脚注为"许多 Follow-up/Composition 实验继承实现"；阈值 ΔAUC > 1e-6 "比噪声低三个数量级"；473 节点消融中 Uniform Random 在 4 个 setting 里的 2 个追平或打败所有 LLM 调度策略，Scenario C 五种策略在小数点后六位全部相同（0.819780）；缺 Oracle 臂与人类工程师基线；批评者预测重标定后晋级率会落到 4–9% 的"progress-over-parent"区间 — [github.com/jjakimoto/research-issues/issues/1749](https://github.com/jjakimoto/research-issues/issues/1749)
- 公共复现尝试仅为"L1 概念 demo"（MovieLens-1M 六个 logistic 变体），明确**不**复现 473 节点生产历史、LLM Agent 或线上 A/B — [github.com/daiwk/auto-research PR#170](https://github.com/daiwk/auto-research/pull/170)

#### 1c. RobustSGPO（快手 + 武汉大学，arXiv 2609.09646，2026-09-09）
- 作者 Zibo Zhao, Jijun Shi, Mo Zhou, Zhongyuan Wang, Shifu Bie, Yunfei Zhang, Xuanting Zhou, Xiangyu Wu, Bin Liu, **Ruiming Tang, Wenwu Ou, Kun Gai**；指出 SGPO 的局部更新规则未解决"编辑范围与操作选择"问题；RobustSGPO 指定编辑请求、构造并检查补丁、可从 incumbent 或保留快照继续搜索 — [arXiv 2609.09646](https://arxiv.org/abs/2609.09646)
- [厂商自述] 30 个 held-out 任务完成率 60.0%→80.0%，测试质量 3.77→4.14（2000 万 token 预算）；在 AgentX brainstorming workflow 上评估：120 任务、95 次运行、7,350 候选尝试；周期性 1→2→3 权限调度比固定最大权限高 0.28 分 — [arXiv 2609.09646](https://arxiv.org/html/2609.09646)

#### 1d. RecSys Factory（腾讯 FiT，arXiv 2608.11241，2026-07-31 提交，2026-08 公开）
- 作者 Dongyang Ao, Kaixiang Fang, Shijie Xu，单位 FiT, Tencent, Shenzhen；21 页、6 图、9 表 — [arXiv 2608.11241](https://arxiv.org/abs/2608.11241)
- 核心原则 "autonomy at decision points, not over pipelines"；提出 autonomy–determinism–efficiency 三难（通用自主：理解运营者意图、零样本生成胶水代码；工业确定性：schema 合规的特征抽取、不崩的 A/B、合规路径零幻觉；端到端效率） — [arXiv HTML 2608.11241v1](https://arxiv.org/html/2608.11241v1)
- 运行时解构为三类宿主事件源：**Claude Code Stop hooks**、企业 IM webhook、工作流调度器 API；等待阶段无常驻 daemon，在 94% 等 Spark/GPU 的墙钟时间里 CPU 占用为零 — [arXiv HTML 2608.11241v1](https://arxiv.org/html/2608.11241v1)
- 能力解构为 29 个 skill 文件（8,971 行 SKILL.md），每个 skill 的 pitfall 表机械编译成 400 条 PitfallStore，把自主权限定在"预先承诺的 pipeline 内的有界、带类型的决策面" — [arXiv HTML 2608.11241v1](https://arxiv.org/html/2608.11241v1)
- [厂商自述] 78 天、3 条业务线（标签语义、A/B 分层拓扑、运营者画像均不同）、1,624 次 CLI 工具派发；Business A（电信个性化）：某运营商各区域 cohort CPM +10–31%，另一运营商 9 个子 cohort 的 rule-fallback 识别"预期提升" +14–45%；Business B（电信重排决策支持）：top-3 子集权重调优建议给出 bootstrap 95% CI 并被运营者采纳；Business C（增长营销）；A 与 C 两条线观察到 onboarding 时间压缩（案例观察） — [arXiv HTML 2608.11241](https://arxiv.org/html/2608.11241)
- 人的角色：以 human-in-the-loop 方式把 Agent 自主权限定在既有工作流中的特定决策点，而不是无限制执行 pipeline — [arXiv HTML 2608.11241](https://arxiv.org/html/2608.11241)

#### 1e. AutoLR（网易，arXiv 2609.04871，2026-09-04）
- 作者 Qi Zhang, Yanlin Chen, Wenchao Xiao，NetEase, Inc.；部署于 **DASHEN（网易大神）** 游戏社区 App，两个推荐场景：单/双列 feed 与沉浸式视频 feed — [arXiv HTML 2609.04871](https://arxiv.org/html/2609.04871)
- 最初构建为 "Auto Launch Review"，后向上游扩展为 research-to-launch harness；自动化研究、辩论、选择、实现、验证、训练、离线评估、候选打包，**而线上 A/B 准入与 Launch Review 保持人工把关（human-gated）** — [arXiv HTML 2609.04871](https://arxiv.org/html/2609.04871)
- 三机制：多专家 Council（角色化 Agent 对同一冻结 briefing 独立分析、互不见初始提案，再辩论与对抗评审）；确定性的 evidence-weighted 探索–利用选择器（分配有限试验预算，用 Council 重排）；分层知识系统（外部研究 + 生产系统知识 + DASHEN 领域知识 + 配置/补丁/日志/失败/离线结果的后验证据） — [arXiv 2609.04871](https://arxiv.org/abs/2609.04871)
- [厂商自述] 数月日志的 path-aware 审计识别出 1,586 个唯一完成评估；9 次生产 Launch Review 记录正向线上提升，三项指标（内容消费渗透、总消费时长、有效内容浏览）**描述性求和**为 +5.75%、+10.83%、+5.55% — [arXiv HTML 2609.04871](https://arxiv.org/html/2609.04871)
- 成本：harness 与循环级优化后，常规迭代从 Claude Opus 级模型迁移到 DeepSeek-V4-Pro/Flash 混合栈，观察到 LLM API 成本约 **3–4 元人民币/迭代** — [arXiv 2609.04871](https://arxiv.org/abs/2609.04871)
- 关键可靠性发现："KEEP ratchet"：噪声晋级会通过 KEEP 棘轮累积，形成看似进步的单调轨迹；结论是自主推荐开发应广泛搜索，但**持久状态变更只能在校准的、确定性的证据下发生** — [arXiv 2609.04871](https://arxiv.org/abs/2609.04871)

#### 1f. Self-Evolving Recommendation System（Google / YouTube，arXiv 2602.10226，2026-02）

## 关键问题 2：技术谱系——AgentX 建立在哪些先行系统之上、如何区别

### Takeaway
AgentX 的直接谱系是 2024–2025 的 ML 工程 Agent（AIDE/MLE-bench、RD-Agent）、进化式代码搜索（AlphaEvolve、Darwin Gödel Machine）与"AI Scientist"式闭环，加上 2020 年前后推荐领域的 AutoML（AutoFIS/AutoCTR）；它的差异在于把**线上 A/B 当 fitness、生产代码库当动作空间、harness 自身当学习对象**，而非在沙盒基准上优化离线指标。

### Cited Findings
- **MLE-bench**（OpenAI，arXiv 2410.07095）：75 个离线 Kaggle 赛题，表格/视觉/语言/音频/时序，单 GPU 24 小时预算；最佳 agent（o1-preview + AIDE）平均 16.9% 赛题拿牌 — [arXiv 2410.07095v6](https://arxiv.org/html/2410.07095v6)
- **AIDE**（Weco）：树搜索 agent，自主起草、调试、评测代码直到用户定义指标最大化；开源 aideml — [MIT AI Agent Index: Weco](https://aiagentindex.mit.edu/2024/weco)；[github aideml 镜像](https://github.com/harit7/aideml)
- **R&D-Agent**（微软，arXiv 2505.14738）：MLE-Bench 上表现最佳的 MLE agent，同一 LLM 后端下明显优于 AIDE（Lite 与 High 组尤甚）；定位"automated research, development, and evolution" — [arXiv 2505.14738v1](https://arxiv.org/html/2505.14738v1)
- **AlphaEvolve**（DeepMind，2025-05）：由 LLM 驱动的进化 pipeline，对代码做变异、评估、选择、跨代改进，用于算法与科学发现 — [二手] [the-decoder / unite.ai 综述](https://www.unite.ai/?p=279107)
- **Darwin Gödel Machine**（Sakana AI + UBC，2025-05）：通过改写自身代码自我改进，SWE-bench 从 20.0% 提升到 50.0%；自发产生补丁验证步骤、更好的文件查看/编辑工具、多方案生成排序、历史尝试记录 — [sakana.ai/dgm](https://sakana.ai/dgm/)
- **AI Scientist**（Sakana，2024-08；v2 2025）：从想法到实验到 LaTeX 论文的全自动流水线；v2 生成的论文被 ICLR 2025 workshop 接收 — [MIT AI Agent Index: The AI Scientist](https://aiagentindex.mit.edu/2024/the-ai-scientist)
- **OpenAI "automated research intern"**：2025-10 Altman 设定 2026-09 实现 intern 级研究助手、2028-03 实现"legitimate AI researcher"；2026-09-07 OpenAI 宣布达成，称研究组织每人类工作日对应 3.1 个 agent 工作日，研究员中位数每天 >600 美元推理花费、头部用户 >7,000 美元/天 [厂商自述] — [TechRadar 2026-09](https://techradar.com/pro/openai-says-it-has-built-an-automated-research-intern-to-carry-out-menial-tasks-and-its-only-just-getting-started)；[Gigazine 2025-10-30](https://gigazine.net/gsc_news/en/20251030-openai-ai-research/)
- **推荐 AutoML 先驱**：AutoFIS（华为，arXiv 2003.11235）两阶段自动选择特征交叉，部署于华为应用市场，10 天 A/B 使 DeepFM 的 CTR +20.3%、CVR +20.1% [厂商自述]；AutoCTR（arXiv 2007.06434）用进化搜索 + learning-to-rank 在 DAG 空间发现交互结构 — [arXiv 2003.11235](https://arxiv.org/pdf/2003.11235)；[arXiv 2007.06434](https://arxiv.org/pdf/2007.06434)；综述 [AutoML for Deep RecSys Survey 2203.13922](https://arxiv.org/pdf/2203.13922)
- 2026 的 ML 工程 Agent 新作把"长程 + 认知积累"作为主题：Cognitive Accumulation for MLE（2601.10402）、MLEvolve（2606.06473）、ScienceFlow（2608.14354）、GEAR genetic autoresearch（2605.13874）、Meta-Agent Challenge（2606.04455） — [arXiv 2601.10402](https://arxiv.org/pdf/2601.10402)；[arXiv 2606.06473](https://arxiv.org/pdf/2606.06473)
- AgentX 自述差异点："not… one-off ML tasks within a sandbox" 而是"continuously drive algorithmic iteration in real recommendation business"，用 online A/B feedback 与 trajectory data 改进系统本身 — [arXiv HTML 2606.26859v2](https://arxiv.org/html/2606.26859v2)
- Harness 进化作为独立子领域：HarnessX "composable, adaptive, evolvable agent harness foundry"（2606.14249）、RRSI "Regularized Recursive Self-Improvement of Agent Harnesses"（2609.24972）、NeoHorse-1 routing harness（2609.08183）均在 2026 年中出现 — [arXiv 2606.14249](https://arxiv.org/pdf/2606.14249)；[arXiv 2609.24972](https://arxiv.org/pdf/2609.24972)

### Inferences
- 谱系映射：AgentX 的 Developing Agent ≈ AIDE/RD-Agent 的"写代码-跑实验-改"循环；Brainstorm Agent ≈ AI Scientist 的 ideation；SGPO/RobustSGPO ≈ DGM 的"修改自身 harness"思想但限定在 prompt/spec 层并要求 paired replay 准入；Evaluation Agent 的 guardrail 否决是推荐领域特有的、先行系统均没有的组件。
- 与 AutoFIS/AutoCTR 的区别：AutoML 在**固定搜索空间**里做可微/进化搜索；AgentX 的动作空间是开放的生产代码（C++/DSL/训练代码），fitness 是延迟、带噪的线上指标而非离线 AUC。
- RobustSGPO 把评测放回"30 个 held-out 任务 + token 预算"，说明快手内部已意识到 harness 进化需要独立于业务 A/B 的离线验证。

### Gaps
- AgentX 论文 Related Work 具体引用了哪些系统（是否点名 AIDE、RD-Agent、AlphaEvolve、DGM、AutoFIS）无法从片段确认。
- AlphaEvolve 的一手白皮书链接在本会话不可访问，仅有二手综述。

## 关键问题 3：快手基础设施背景——OneRec 栈、内部 LLM、实验与训练平台、先前 Agent 工作

### Takeaway
公开资料显示快手在 2025–2026 年把推荐主线押在 OneRec 生成式架构（OneRec→V2→Think→OpenOneRec/OneReason），同时拥有自研编码模型线（KwaiCoder/KAT-Coder，内部 Kwaipilot）；但**没有任何可得片段表明 AgentX 引用 OneRec 或说明其运行于 OneRec 栈**——AgentX 的编码失败分析显示其操作对象是 C++/DSL/MaTX 的传统策略与模型 pipeline。

### Cited Findings
- **OneRec（2502.18965，2025-02）**：端到端生成式推荐，session-wise 生成 + MoE，取代召回-粗排-精排级联；总观看时长 +1.68%（另一片段称主场景 watch-time +1.6%）[厂商自述] — [arXiv 2502.18965](https://arxiv.org/html/2502.18965v1)

- **OneRec-V2（2508.20900，2025-08）**：Lazy Decoder-Only 架构消除 encoder 瓶颈，总计算 −94%、训练资源 −90%，扩展到 8B；Duration-Aware Reward Shaping + Adaptive Ratio Clipping；主站/极速版 Stay Time +0.467% / +0.741% [厂商自述] — [arXiv 2508.20900](https://arxiv.org/abs/2508.20900)
- **OneRec-Think（2510.11639，2025-10）**：In-text reasoning；"Think-Ahead"架构部署于快手，1.29% 流量实验组对比线上模型一周，APP Stay Time +0.159% [厂商自述] — [arXiv 2510.11639](https://arxiv.org/html/2510.11639v1)
- 后续：OpenOneRec Technical Report（2512.24762）、OneReason Technical Report（2606.06260）、OneMall（快手电商生成式家族，2601.21770）、OneLive（直播，2602.08612）、Kwai Summary Attention（KSA，2026-04-28，开源 kernel 与训练 recipe）、KUAISHOU Explorer LLM-Rec Challenge 2026（2609.39828） — [arXiv 2512.24762](https://arxiv.org/pdf/2512.24762)；[arXiv 2606.06260](https://arxiv.org/pdf/2606.06260)；[github Kuaishou-OneRec/KSA](https://github.com/Kuaishou-OneRec/KSA)；[arXiv 2609.39828](https://arxiv.org/abs/2609.39828)

- **先前 Agent 工作**：KwaiAgents（KwaiKEG，2023-11 发布，arXiv 2312.04889）：KAgentSys-Lite、KAgentLMs、20 万条 KAgentInstruct、KAgentBench；7B 模型人评 67.66% 接近 GPT-3.5-turbo 68.66% — [github kwaikeg/kwaiagents](https://github.com/kwaikeg/kwaiagents)

### Inferences
- AgentX 运行在传统"策略 pipeline（C++/DSL）+ 离线模型训练 pipeline"上，而非 OneRec 的单一生成式模型；MaTX 很可能是快手内部的 C++ 模型/策略框架名（仅出现在失败归因片段，性质未确认）。OneRec 栈与 AgentX 更像并行的两条主线，而不是前者承载后者。
- OneRec 系列报告给出了快手 A/B 实践的公开参数（1–5% 流量、一周观察、主指标 App Stay Time + LT7、显著后扩至 25% QPS），可作为理解 AgentX "三周 10 个全量"节奏的参照。
- KAT-Coder/Kwaipilot 的存在使快手有能力用自研编码模型跑 AgentX，但 A/B Agent 用 GLM-5.1、AutoLR 用 Claude→DeepSeek，说明国内团队并不默认使用自研基座；AgentX 基座仍是未知数。

### Gaps
- AgentX 是否引用 OneRec：未找到任何证据（既无正面也无反面）。
- 快手实验平台（分层/holdout 设计）、训练平台名称与规模：公开论文仅零散给出 MFU 与流量比例，无平台级描述。
- "MaTX"的确切含义未确认。

## 关键问题 5：批判性阅读——评估方法论共性问题与独立研究者对"Agent 跑 A/B"的风险看法

### Takeaway
这批论文共享四类弱点——"vs 工程师"基线不可复现、窗口短（AgentX 三周、RecHarness 七天、OneRec 一周）、分母/阈值自定义带来的选择效应、以及收入归因缺少对照；独立批评者已指出 AgentX-Model 的"560/636"用了低于噪声三个数量级的阈值且随机策略追平 LLM 策略，而实验学界（Kohavi 等）与 2026 年的自进化 Agent 安全文献分别从多重比较、新奇效应与"misevolution"角度给出了系统性风险框架。

- [独立] 对 AgentX-Model：ΔAUC>1e-6 阈值"比噪声低三个数量级"；"above baseline"混入继承实现；Uniform Random 在 4 个 setting 中 2 个追平/打败全部 LLM 调度；缺 Oracle 与人类基线；预测重标定后晋级率落到 4–9% — [research-issues #1749](https://github.com/jjakimoto/research-issues/issues/1749)

### Inferences
- "vs 工程师"对比（AgentX 的 8×/13.8×/3.7×、Auto-RecSys 的 hours→minutes）在所有论文中都没有对照组、样本量或时间仪表化，属于不可复现的叙事性基线；按 #1459 的标准，需要预注册两臂试验才能成立。
- Agent 以周为单位高并发开 A/B（AgentX 单 worker 12 并发）会把 Kohavi 所说的 26% 假阳性风险与多重比较问题系统性放大；AgentX 的 "guardrail veto" 只控制"下行"，并不解决"上行是假阳性"的问题——AutoLR 的 KEEP ratchet 正是对此的实证警告。
- 收入归因（AgentX 的"年化 >1 亿元"）是把短窗口 A/B 增量外推到全年，未扣新奇效应衰减；OneRec 系列同样以一周 1–5% 流量做主报告，说明这是快手公开报告的通行惯例而非 AgentX 独有。
- SGPO 式"harness 自我修改"落在 misevolution 文献的"workflow / memory 进化"风险路径上；RobustSGPO 引入快照回退与权限调度，可视为对该风险的部分回应。
