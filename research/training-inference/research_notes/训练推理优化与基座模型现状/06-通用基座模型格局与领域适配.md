## KQ1 开源/开放权重模型版图（截至 2026-10）

### Takeaway
截至 2026-10，开放权重前沿由中国厂商主导（DeepSeek V4 系列、Qwen3.5/3.6/3.8、Kimi K3、GLM-5.x、MiniMax M2.x/M3、Hy3/Hy4、MiMo-V2），参数规模已到 1.6T–2.8T 总参/50B–100B 激活，上下文普遍 256K–1M，许可证以 MIT / Apache 2.0 为主（Kimi 与 MiniMax 用“带 1 亿 MAU 署名条款的 Modified MIT”，腾讯旧版 Hunyuan 许可排除欧盟/英国/韩国且 >1 亿 MAU 需另行授权，Llama 4 >7 亿 MAU 需 Meta 授权）；美系开放权重只剩 gpt-oss（2025-08，之后无续作）、Gemma 4（2026-04，首次 Apache 2.0）、Llama 4（2025-04，后续 Avocado 据报道闭源）、Mistral 3（2025-12）、NVIDIA Nemotron 3。对推荐/内容理解团队而言，"30B-A3B 级 MoE（Qwen3.5/3.6-35B-A3B、Qwen3-VL-30B-A3B、Keye-VL-2.0-30B-A3B、Nemotron 3 Nano）+ 8B 以下 dense（Qwen3-8B、Qwen3.5-9B、Gemma 4、InternVL3.5-8B）"是 2026 年被工业界反复选用的"可微调、可自部署"档位，而 300B–700B 级（DeepSeek V3.2/V4-Flash、GLM-5.3-Flash、Hy3、MiMo-V2-Flash、Qwen3.5-397B-A17B）主要作为离线打标/蒸馏教师或 API 使用。

## KQ2 架构趋势及其对推理成本的影响

### Takeaway
2025 年中至 2026 年 10 月的开放权重架构演进可概括为“更稀疏的 MoE（激活比 1:16→1:50，专家数 256→896）+ 亚二次注意力（稀疏 DSA/CSA/MSA/QSA 或线性 GDN/KDA/Mamba 混合，或 5:1 滑窗交错）+ 原生 MTP 投机解码 + 低比特原生权重（FP8→MXFP4/NVFP4/INT4 QAT）”，共同效果是：同等能力下激活参数降到 3B–20B、长上下文（256K–1M）KV cache 降 4–10×、解码吞吐提升 2–6×；代价是训练/推理框架复杂度上升（专用 kernel、EP/DP 并行、indexer cache），以及 thinking 模式带来的输出 token 数量级膨胀（单任务数百万 token），后者正通过思考预算、reasoning_effort 分级和“潜空间推理”来治理。

### Cited Findings

#### MoE 稀疏度与专家粒度
- Kimi K2 的稀疏度 scaling law（固定激活参数/FLOPs）：稀疏度（总专家数/激活专家数）48 相对 8/16/32 在同验证损失下节省 FLOPs 1.69×/1.39×/1.15×，“稀疏度越高越好，但基础设施更复杂”，因此选 384 选 8；同时把注意力头从 DeepSeek-V3 的 128 减到 64 以降低推理开销 — [Kimi K2 tech_report.pdf](https://github.com/MoonshotAI/Kimi-K2/blob/main/tech_report.pdf)（2025-07；A）

### Inferences
- 对推荐/内容理解负载（输入长、输出短：商品/视频描述 + 用户序列 → 标签/分数/SID）而言，最相关的成本杠杆依次是：激活参数（决定每 token FLOPs，3B 激活 MoE 已足够承担打标）、prefill 成本（稀疏/线性注意力与 V4.1 式“prefill 少激活”直接受益）、以及是否需要 thinking（显式 CoT 会让输出 token 从几十膨胀到数千，潜推理/Think-Ahead 是工业界 2026 年的共识解法）。
- 架构红利的兑现强依赖推理框架：GDN/KDA 需要 fla/causal_conv1d 内核，DSA 需要 FlashMLA/DeepGEMM 的 indexer kernel 与专门的缓存层，MSA 需要专用 top-k kernel；自部署团队若使用 vLLM/SGLang 主线一般可在模型发布的数周内获得支持（上述模型均有官方 recipe），但在非 NVIDIA/非主线硬件上的回退路径可能慢一个数量级（MiniMax M3 FP8 7× 慢、Qwen3.5 GDN 回退“更慢更耗显存”）。
- MTP 已成默认配置而非可选加速：2025 下半年后发布的主流 MoE（DeepSeek、GLM、Qwen3-Next/3.5、MiMo、Hy3/Hy4、Nemotron、Ling）几乎全部原生自带 MTP 层，预期 2–3× 解码加速，对短输出的打标任务收益小于长生成任务。
- 2026 年的新一代结构变化（mHC/AttnRes/Gated Residual、N-gram/Engram 记忆、hash-MoE 引导层）主要作用于训练效率与 scaling 效率（官方口径 1.25×–2.5×），对推理成本的直接影响有限，但意味着这些底座的 HF 实现需要 transformers 5.x 级别的新模型类，微调工具链（LLaMA-Factory/ms-swift/verl）的跟进存在时间差。

### Gaps
- 没有任何一份官方材料给出"同硬件、同负载"下跨厂商的 $/百万 token 自部署成本对比；本文的成本比较只能基于各家自报的吞吐、FLOPs 比例与 API 定价。
- MiniMax M2/M2.x 的注意力类型（是否完全放弃线性注意力）未在 README 中声明；Gemma 4 与 gpt-oss 的滑窗层比例未取得官方数字。
- 思考模式在推荐类任务上的"准确率-token"曲线仅有 Seed-OSS 的定性描述与推荐系统论文的相对数字，缺乏可复用的定量基准。

## KQ3 领域适配技术与证据（推荐 / 广告 / 电商 / 内容理解）

### Takeaway
2025H2–2026 的工业界公开案例收敛到一条相当一致的适配配方：**“Semantic ID / itemic token 扩词表 → 继续预训练（CPT/co-pretraining，混入通用文本防遗忘）→ 多任务 SFT → RL（GRPO/GSPO/DAPO 变体 + 业务奖励）→ 蒸馏/潜推理压成本”**，底座多为 1.7B–8B dense（Qwen3-1.7B/8B、Llama 3.1 8B）或 ~1B 激活的 MoE（YouTube PLUM 900M 激活、Gemini-1.5 MoE 家族），在线服务普遍采用 prefill-only / 离线异步 / 蒸馏到小模型等手段；报告的在线收益多在 +0.1%～+5% 的核心指标区间（App 停留时长、CTR、GMV、转化），同时伴随 50–90% 的计算或 OPEX 下降声明。

### Inferences
- 底座大小的工业选择呈现“双峰”：在线/近线路径上用 ≤8B（Qwen3-1.7B/8B、Llama 3.1 8B、SARA-7B、Keye-VL-8B）或 ≤1B 激活 MoE（PLUM 900M 激活）；离线教师/打标用 20B–100B 激活的大模型（Rec-Distill 24B dense 教师、Meta GEM、RGCD-Rep 冻结教师 MLLM）。没有公开案例把 >30B 激活的 LLM 直接放在毫秒级排序路径上；凡是上线的，都通过 prefill-only、潜推理、离线预计算、蒸馏或缓存把 LLM 开销从在线路径移走。
- CPT 的核心价值被多家独立验证（PLUM、OpenOneRec、SnapLGR、美团蒸馏教师）：新 token（SID/itemic）必须先在混合语料上“落地”，否则 SFT 阶段幻觉率与遗忘严重；OpenOneRec 的 1.7B→8B 与 33B→130B token 的递增收益，以及 PLUM 到 900M 激活仍未饱和的 scaling，说明在推荐任务上参数与领域 token 量都还有可预测的回报（推断）。
- RL 已经从“推理能力”延伸到“业务奖励对齐”：GR4AD（RSPO）、OneMall（排序模型作奖励）、Taiji（POPO 双奖励权衡）、OneRec-V2（时长感知奖励）、QP-OneModel（多奖励 RL）都在 2026 年给出在线增益，算法上多为 GRPO/GSPO/DAPO 的列表级或多奖励变体；这意味着团队需要 verl 级别的 RL 基础设施而不只是 SFT 工具链。
- "适配后模型大小与服务成本"的公开量化仍稀缺但方向一致：PLUM 训练成本与 LEM 相当、OneRec OPEX 10.6%、RecGPT-V3 服务资源 −52.4%、MixLM 吞吐 10×、AIR 400×、WhisperRec >10×——降本主要来自把 LLM 从每请求在线推理中移出，而非模型本身更便宜。

### Gaps
- Rec-Distill 的作者单位与底座类型（是否为 LLM）未在摘要中给出；360Brew 的底座（Mixtral vs Llama）只有演讲摘要与第三方说法，论文全文不可达。
- RecGPT-V2/V3、ConnectionMind、GenRec、GLIDE、GR4AD 等均未在摘要中披露所用 LLM 底座及其参数量；GenRec 仅说“开源 LLM”。
- OpenOneRec 技术报告全文（含训练算力、GPU 小时）不可达，本地克隆也没有 PDF；本文只能给出脚本中的超参与 README 结果。
- 没有找到 TikTok/字节推荐系统直接使用 Seed/Doubao 基座做推荐适配的公开论文（字节公开的相关工作为 HLLM/HLLM-Creator、SAIL-Embedding、DME、“Make It Long”10k 序列等，均未声明底座型号）。
