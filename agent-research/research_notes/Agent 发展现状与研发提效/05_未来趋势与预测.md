## 关键问题 1：能力趋势线（METR 时长、编码/计算机操作基准、发布节奏、价格、上下文）

### Takeaway
2024 年后 METR 50% 任务时长的倍增期已缩短到约 4 个月（105–131 天），2026 年初前沿从约 5.5 小时跳到约 14–16 小时；SWE-bench Verified 已饱和（前沿 >95%，OpenAI 2026-02 宣布停止汇报），行业基准转向 SWE-bench Pro（Scale 标准化集约 50–60%，厂商自报已达 78–90%）、Terminal-Bench 2.0（~83%）、OSWorld-Verified（~85%）。token 价格以每年数十倍的"同等能力价格"速度下降，但旗舰推理模型价格几乎不降；1M 上下文成为旗舰标配但"有效上下文"只有标称的 50–65%。

### Inferences
- `[推测]` 若 4 个月倍增期延续到 2027 年底，50% 时长将从 2026 中的约 12–16 小时升至数周量级；若如 LessWrong 分析所言回落到 7 个月，则 2027 底约 40–60 小时（一周工作量）。两种情形下，"单任务跑一整天"都会在 12–24 个月内成为常态；但 80% 可靠性时长滞后约 2 个数量级（3 小时 vs 16 小时），**可靠性而非能力才是内部落地的瓶颈**。
- `[推测]` SWE-bench Verified 的饱和与 OpenAI 停报说明：公开基准寿命约 18–24 个月；内部团队应假设任何公开编码基准都会在 2 年内饱和，自建私有评测集的价值随之上升。
- `[推测]` 旗舰价格不降而"同等能力价格"每年降 50×+，意味着 12 个月后今天的旗舰能力将以中档价格可得；长程 Agent 的成本问题会被模型降价部分化解，但 token 用量随时长超线性增长，仍需工程侧压缩/缓存。

## 关键问题 2：自主性预测——实验室与独立预测者说了什么，哪些已被证实/证伪

### Takeaway
实验室预测中"AI 写大部分代码"在实验室内部已兑现、在普通企业未兑现；OpenAI 自报于 2026-09 达成"自动化研究实习生"（3.1 个 agent 工作日/每人类工作日），下一目标 2028-03"自动化研究员"。独立预测者分化：AI 2027 作者承认"比情景慢"、AGI 中位推后到约 2030；Metaculus 社区 AGI 中位数 2033；FRI 发现专家与超级预测者系统性**低估**基准进展但其对"80% 可靠任务时长"的预期仍很保守（3.4 小时）。

## 关键问题 6：风险与逆风

### Takeaway
可靠性与成本是长程 Agent 的核心技术逆风（80% 时长远小于 50% 时长；critic 提升成功率但成本升 5.6×；长轨迹耗百万 token 而进展甚微）；Gartner 2026-04 首次发布独立 Agentic AI Hype Cycle，将其置于"期望膨胀顶峰"并预测 >40% 项目 2027 底前被取消、仅约 130 家供应商"真实"；监管上 EU AI Act GPAI 义务 2026-08-02 开始执法（最高 3% 全球营收），中国 2026-07-15 实施首个 Agent 专门框架（三级权限分层）；安全上 prompt injection 仍居 OWASP LLM Top 10 之首且被视为架构性未解问题；能源上 30–50% 计划 2026 开业的大型数据中心延期/取消。

### Cited Findings

**可靠性与成本**

## 关键问题 7：综合——12–24 个月内将被商品化的能力 vs 持久的内部优势

### Takeaway
基于上述趋势，12–24 个月内（到 2027 底–2028 中）模型/平台厂商大概率会商品化：数小时至数天的自主编码任务、云沙盒多 Agent 编排、1M 上下文与自动压缩、基础持续记忆、通用计算机操作/浏览器操作、critic/验证器模型、MCP/A2A 互操作、按结果计费的部分场景。持久的内部优势集中于：私有上下文（推荐系统架构知识、历史实验、线上指标语义）、内部工具的声明式接口、私有评测集与 RL 环境、数据与工作流、安全/合规分级制度，以及把这些组织成"可训练、可验证的环境"的能力。

### Cited Findings
（本节为综合，直接证据已在前六节给出，此处仅列支撑该综合的关键锚点）
- 三大编码 Agent（Claude Code / Codex / Jules）均已内置云沙盒、后台任务、多 Agent 并行与 PR 回传 `[二手]` — [digitalapplied Q2 2026](https://www.digitalapplied.com/blog/claude-code-vs-codex-vs-jules-q2-2026-matrix)；[VS Code 多 Agent 博客](https://code.visualstudio.com/blogs/2026/02/05/multi-agent-development)

### Inferences
`[推测]` **12–24 个月内大概率被商品化（不要自建）**：
1. 通用编码 Agent 内核（规划、工具调用、代码编辑、测试运行、PR 生成）——已被三大厂 + 开源模型覆盖，METR 时长每 4–7 个月翻倍意味着任何自研内核在半年内落后。
2. 任务编排与沙盒基础设施（并行会话、后台任务、agent 仪表盘）——Claude Code agents / Codex cloud / Jules / VS Code 多 Agent 均已产品化。
3. 上下文管理（1M 窗口、自动压缩、检索）——厂商在竞争有效上下文；自建压缩方案价值衰减快。
4. 基础持续记忆（跨会话规则蒸馏）——学术共识已形成，Letta 等产品存在，厂商会内置。
5. 通用计算机操作/浏览器操作——OS 厂商转向原生能力声明接口，通用 GUI Agent 自建无意义。
6. Critic/验证器基础模型与"多次采样 + 评审"模式——厂商在 Opus 5 等发布中已强调"验证自身工作"。
7. 协议互操作（MCP、A2A）——已是事实标准，自定义协议只会增加迁移成本。

`[推测]` **持久的内部优势（应投资）**：
1. **私有上下文的结构化**：推荐系统架构图谱、服务依赖、历史实验与结论、指标语义、事故复盘——以可检索/可注入形式（文档、知识图、MCP 资源）维护。这是任何外部模型都没有、也无法在 1M 上下文中"自然"获得的。
2. **内部工具的声明式接口**：把特征平台、A/B 平台、离线评测、训练调度、监控等暴露为 MCP 工具/声明式能力，而不是让 Agent 操作 UI。这与 OS 厂商方向一致，且是 Agent 真正能"动手"的前提。
3. **私有评测集与 RL 环境**：公开基准 18–24 个月饱和且被厂商自报分数稀释；以内部真实任务（含历史 PR、实验配置、线上问题）构建的评测集与可训练环境既是选型依据，也是与供应商议价/定制和微调开源模型的筹码。
4. **验证与验收层**：针对推荐系统的领域验证（离线指标回归、流量影响估计、特征泄漏检查、线上灰度规则）——80% 可靠性时长仅 3 小时的现实下，自动验收是把 50% 能力转为可用产出的关键。
5. **安全与合规分级**：按中国 2026-07 三级权限 + Willison 致命三角设计 Agent 的权限边界、审计日志、人工批准点；这既是合规必需也是可复用资产。
6. **工作流与数据**：实验 → 分析 → 决策的内部节奏数据，用于训练/评估"研究实习生"级 Agent；OpenAI 的 3.1 agent-workday 口径提示应尽早建立内部"Agent 工作日/人类工作日"与"产出被采纳率"度量。
7. **开源底座能力（可选）**：若数据不可出境或需要 RL 微调，保留在 MIT 许可开源模型（DeepSeek V4 / GLM-5.2 / Qwen3.x）上微调的能力，但以内部评测集决定是否值得。

`[推测]` **时间表假设（供规划）**：
- 2026Q4–2027Q2：前沿 50% 时长 ~1–3 个工作日、80% 时长 ~4–8 小时；企业 Agent 项目进入幻灭期；EU 执法与中国 Agent 框架落地。
- 2027H2：OpenAI 等推进"自动化研究员"中间里程碑；RL 环境与 critic 模型普及；AI 2027 作者中位数的 Automated Coder（2028 中）尚未到达。
- 2028：各方预测的"自动化 AI 研究员"（OpenAI 2028-03）与 AI Futures AC 中位（2028 中）交汇点；若兑现，内部 ML 研发 Agent 的瓶颈完全转为私有上下文、环境与验收。
